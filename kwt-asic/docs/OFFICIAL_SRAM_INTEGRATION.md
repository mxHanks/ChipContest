# 官方 SRAM 接入手册

当前状态：官方功能模型、引脚手册、SRAM Liberty/LEF 及面积/功耗数据尚未提供，`OFFICIAL_MACRO` 为 **BLOCKED**。本仓库的通用端口仅定义内部存储事务，不是对官方宏引脚的猜测。

材料接收先填写`configs/official-sram-package.json`并运行[分阶段预检](OFFICIAL_SRAM_INPUT_READINESS.md)。simulation文件核验不等待power/area，仿真和综合分别给出源集，Liberty可跨角色引用同一文件。该入口只检查身份/分类，不替代实际HDL编译、模块/端口和功能/PPA；不会修改旧配置READY。现有开发CLI尚未接通official，需要在真实包到位时按本文接通并重验。

## 当前接口和替换边界

`kwt_linear_engine_rowpair_sram` 通过 `kwt_sram_bank` 拼接容量与位宽，再调用 `kwt_sram_1rw`。原有 `kwt_linear_engine_rowpair` 保留作独立对照。原语后端参数 `BACKEND` 为 0=行为仿真、1=综合黑盒、2=FF fallback、3=外部官方 adapter。宏到位后新增 `kwt_official_sram_adapter`，仅在官方模式显式文件集中加入；不应编辑 MAC、Golden 或数值格式来配合存储模型。

逻辑接口为上升沿采样的单端口事务：`wr_en/wr_addr/wr_data` 或 `rd_en/rd_addr`，同周期最多一种；读数据在采样沿后可用，对应下一周期的 `rd_valid=1`。无读请求时当前模型保持 Q。复位只清 valid/control，不清存储内容；合法任务必须完整装载 X、W、bias。双结果缓冲分别访问独立 bank，没有单个双端口宏需求。读写并发和同址碰撞均禁止且仿真检测，不能把任何供应商未定义的碰撞值作为正确功能。

`rd_valid` 由 wrapper 生成，不假定宏有此管脚；宏本身不接复位。若官方 Q 在禁用时不保持，应在 adapter 加保持寄存器；若官方读延迟不是一拍，必须显式适配并评估对状态机和吞吐的影响，不能只改 `rd_valid` 延迟。若无法保持当前一拍契约，先修改上层等待/标签流水，再重跑全部功能与性能验证。

## 候选拼接及暂定内容

当前候选为 20 个逻辑 bank、72 个 16-bit 原语，配置容量 56.5 KiB，逻辑有效容量 415,744 bit。原语形状为 50×(128×16) 和 22×(1024×16)，未用 4096 深度；它们是按赛题允许容量做的逻辑拼接，**尚未实例化官方宏**。深度片选在读采样时保存一拍，选择对应返回数据；高于逻辑宽度的物理字位填零且读出忽略。40-bit bias 和41-bit结果均用3片16-bit并联。

| 逻辑对象 | bank 数与形状 | 候选16-bit配置 |
|---|---|---|
| X 偶/奇行 | 3200×16、3136×16各1 | 每bank 3×1024+1×128 |
| W | 8×2048×16 | 每bank 2×1024 |
| bias | 8×32×40 | 每bank 3×128，宽并联 |
| 结果 | 2×512×41 | 每bank 4×128×3宽片 |

尚待确认：真实宏支持的端口模式、读延迟/输出保持、使能/写使能极性、写掩码粒度、地址顺序、休眠/测试/电源管脚、同址规则、最小周期及所有时序弧、PVT、面积单位、功耗表、官方允许的宏组合及面积统计规则。512 KiB **E203共享 SRAM** 独立于这些内部 bank，不能把内部 bank 纳入共享容量后假称面积豁免。

## 文件接入步骤

1. 将官方交付包原样放在项目规定的只读技术目录或外部授权路径，记录来源、许可证、版本、SHA256；不能修改官方模型使测试通过。
2. 在 `tech/official_sram/` 建立显式配置，分别列功能 Verilog、setup/hold/power Liberty、LEF/其他必需文件和角。不要递归收集整个包，也不要同时编译通用黑盒与同名官方模块。
3. 实现 `kwt_official_sram_adapter`，保持本仓库通用参数/端口；在 generate 中只允许已核实的16×128/1024/4096组合，非法形状立即失败。把真实宏的极性/测试管脚/写掩码转换集中在此文件，保留绑定手册页码。
4. 仿真源集选择 `BACKEND=3` + 官方功能模型；综合源集选择同一 adapter + 官方宏 Liberty/定义。两者使用同一宏清单/参数/布局配置。黑盒不是功能模型。
5. 核对官方模型与当前逻辑契约。必要的保持寄存器、延迟适配和流水有效标签必须同时存在于仿真与综合；不允许只在仿真路径补偿。

## 当前接入准备与必须重验项（2026-10-18）

核心/ICB/SoC及综合入口已读取`configs/sram-backends.json`并由`sram_sources.py`选择显式开发源集，source identity绑定配置和选择器SHA。冻结v1官方分支仍要求完整材料且CLI未开放official；默认BLOCKED正确，不能把占位接口当官方pin定义。现在新增独立预检支持分批材料分类，实际官方构建仍需消费已核准的计划并完成真实编译和回归，不能只填旧READY。旧选择器/生产脚本未因材料预检而修改，既有开发证据不因此失效。

已完成12层开发SoC（含恢复和全部写响应）可作接入后的功能对照；官方Adapter、功能模型或延迟变化使该模式的旧证据失效，必须重新跑相应测试。即使正式宏满足一拍，也须重做macro端口/保持/碰撞负例、所有bank切片、原版/行为/FF/官方输出对照和完整CPU联调。

Nangate45参考流程显式绑定其库默认统计wire-load模型5K_hvratio_1_1；不是官方互连或提取寄生。独立参考ECO后，已覆盖setup/data hold/removal为正，候选12层门级场景回放通过；全输入形式仍NOT_PROVEN。参考hold仅1.379ps，官方角/线负载/时钟/IO条件必须替换为正式数据并重新生成报告，不能沿用参考正Slack或把当前buffer级数、BUF/NOR4强度当作官方实现。官方宏输入电容未知也不能补零。


原语/bank层现有独立[BACKEND=3契约入口](OFFICIAL_SRAM_CONTRACT_RUNNER.md)，默认消费simulation材料计划，缺包不启动HDL；显式开发夹具资格化不算官方宏通过。旧核心/ICB/SoC CLI仍保持开发源集，真实模型及后续接线尚待完成。


真实Adapter接入后还需运行[覆写/reset补测](SRAM_UPDATE_RESET_VALIDATION.md)。现有开发三后端已有24场景/1080检查，但官方模型仍NOT_RUN；不能把开发夹具的reset屏蔽或覆写结果直接继承给供应商模型。
