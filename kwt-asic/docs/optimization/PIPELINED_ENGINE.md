# 首个优化候选：乘积寄存与偏置读使能

日期：2026-10-15。候选文件：`src/rtl/kwt_linear_engine_opt.sv`。

本候选从当前 `kwt_linear_engine` 派生，原模块、原测试入口和 vendor 不变。计算形状、fixed16_acc48_v1 数值契约及所有外部端口保持一致；新增 `PIPE_MUL` 参数，默认 1，允许 0/1。`LANES` 仍默认 8，且须为 256 的正因数。非法参数在 elaboration 阶段拒绝。

这一步只隔离两个变化：乘法输出寄存，以及每组偏置只读一次。它没有实现双行权重复用、写回重叠、指定 SRAM 或 E203 接口。功能测试、工艺时序、面积和完整系统能耗必须分别以实际报告验收。

## 数据通路与时序

`PIPE_MUL=0` 的结构为：

```text
同步 X/W 存储读寄存器 → 16×16 有符号乘法 → 48 位加法 → acc
                                    首项加法输入来自保持的 bias
```

`PIPE_MUL=1` 的结构为：

```text
同步 X/W 存储读寄存器 → 16×16 乘法 → 32 位 product 寄存器
                                                  ↓
                                     48 位符号扩展与加法 → acc
                                        ↑ 首项选 bias，其余选 acc
```

这是给乘法输出加寄存边界，将原来的乘法及累加长路径分成两个阶段；**不是将 16×16 乘法器内部的部分积再切为多级**。乘法器自身是否能在指定库/PVT 下通过 150 MHz，仍需 STA 确认。

每周期仍能发射一个归约项，对 LANES 个输出通道并行计算。额外寄存只增加每个 64 项点积组的排空周期，不降低稳定发射率。累加反馈保持每周期一项，不需要多上下文交错累加。

以一个输出组的第一次读取为边沿 T0：

| 边沿 | SRAM 读 | PIPE_MUL=0 | PIPE_MUL=1 |
|---|---|---|---|
| T0 | X/W 的 k=0、该组 bias | 读取元数据进入 read_* | 同左 |
| T1 | X/W 的 k=1 | acc = bias + product(k=0) | product(k=0) 与 first 标签寄存 |
| T2 | X/W 的 k=2 | acc += product(k=1) | acc = bias + product(k=0)，product(k=1) 寄存 |
| T63 | X/W 的 k=63 | 累加 k=62 | 累加 k=61、寄存 k=62 |
| T64 | 不再读 | 累加 k=63，进入 EMIT | 累加 k=62、寄存 k=63 |
| T65 | 不再读 | 接收第一个输出（若 ready） | 累加 k=63，进入 EMIT |
| T66 | 不再读 | 继续输出 | 接收第一个输出（若 ready） |

`read_valid/first/last` 同步于 SRAM 读数据；流水模式把三项标签延迟一拍，得到 `accumulate_valid/first/last`。DRAIN 等 `accumulate_valid && accumulate_last` 后才发布结果，确保最后一项已经进入 acc。乘积和偏置按各自原宽度进行符号扩展，不依赖无符号表达式提升。

## 偏置读取

内部可观测读使能为：

- `x_rd_en = (state == COMPUTE)`，每次使能读取一个 16 位字。
- `w_rd_en = (state == COMPUTE)`，每次使能读取 LANES 个 16 位字。
- `b_rd_en = (state == COMPUTE && k_issue == 0)`，每次使能读取 LANES 个 40 位字。

偏置在 T0 读取，至少在 T1 前可用；PIPE_MUL=1 在 T2 才使用它。`b_read` 在当前组期间保持，下一个组在前一组所有输出接收后才开始，因此偏置不会与前一组在途乘积重叠。第 0 项之后的 63 次偏置重复读取被禁止。

单任务逻辑读取字数：

| 对象 | 原基线 | 本候选（两种 PIPE_MUL） |
|---|---:|---:|
| X，16 位字 | 99 × (256/LANES) × 64 | 相同 |
| W，16 位字 | 99 × 256 × 64 = 1,622,016 | 相同 |
| bias，40 位字 | 99 × 256 × 64 = 1,622,016 | 99 × 256 = 25,344 |

bias 的逻辑读使能次数减少 98.4375%，它不是 SRAM 或整机能耗降低百分比。偏置宽度拆分成 16 位宏、宏真实 CE/时钟行为、地址切换、外围寄存器以及其他模块活动均需纳入功耗测量。综合还可能对恒定地址的重复读取进一步优化，应以映射后网表及活动数据为准。

## 周期及资源推导

无输出回压时：

```text
core_cycles = 99 × (256/LANES) × (64 + 1 + PIPE_MUL + LANES)
```

| LANES | PIPE_MUL=0 | PIPE_MUL=1 | 流水额外周期 |
|---:|---:|---:|---:|
| 8 | 231,264 | 234,432 | 3,168（1.37%） |
| 16 | 128,304 | 129,888 | 1,584（1.23%） |

流水本身不减少固定频率下的周期数；它用少量周期和寄存器开销换取潜在时序裕量。若两种版本都通过目标 150 MHz，必须进一步比较面积、能耗及完整任务时延再选择，不能仅因增加流水就宣称更快。

PIPE_MUL=1 比同候选 PIPE_MUL=0 增加 `32 × LANES` 位乘积寄存器和 3 位控制标签寄存器，默认是 256+3 位。实际标准单元面积受综合合并、时钟门控、复位映射等影响。X/W/bias 的逻辑容量不变，仍为 46,720 字节；指定宏取整及接口逻辑面积还未计入。

`core_cycles` 定义维持原模块：从启动后的 busy 周期到最终输出握手，包含输出回压，32 位饱和。它不包含装载、CPU 调度、总线和外部最终写回，不能作为官方完整窗口性能。

## 数值范围与后续候选

当前 acc 保留 48 位以隔离流水影响。对任意合法 16 位 X/W、40 位 bias，任意归约部分和满足：

```text
abs(partial_sum) <= 2^39 + 64 × 2^30 = 2^39 + 2^36 < 2^40
```

因此有符号 41 位内部累加、最终符号扩展到 48 位在数学上足够；40 位不够。41 位可作为独立候选，须保留极值及正负抵消回归，并对相同工艺/约束比较面积、延迟和能耗后再采用。本轮未混入该变化。

## 不变协议与验证风险

- 加载仍每类从 0 连续到末地址，三类可交错；非法传输置 sticky error，运行中不接受加载或启动。
- 每任务完成清空完整装载计数，下一任务必须重装；没有跨任务缓存参数。
- 输出仍严格按行优先 0..25,343，`valid && !ready` 期间数据、索引及 last 必须保持。
- 所有在途有效标签均异步复位清零；payload RAM、乘积、累加器不清零。复位中断后完整装载和首项覆盖防止旧数据发布。
- PIPE_MUL=1 特别需要在首次发射、末项排空、输出回压时复位的检查；标签错一拍可能只在全形状最后一项或换层时显现。
- SRAM 宏需要保持同步读延迟约定；未来若宏增加输出寄存或不同 CE 语义，必须重新对齐标签。
