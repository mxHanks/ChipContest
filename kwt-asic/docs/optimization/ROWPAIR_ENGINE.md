# 双行权重复用 AI Engine 候选

状态：独立候选，保留原迁移和 banked RTL。本文描述 `src/rtl/kwt_linear_engine_rowpair.sv` 的实现及可检验推导；RTL 回归、结构综合与指定工艺结论分别以对应运行报告为准。指定 SRAM 映射、150 MHz 时序、面积、功耗及 E203 完整窗口尚未验收。

## 运算和存储

固定 2 行 × 8 输出列，共 16 个 16×16 乘法器。每个时钟从 8 个 W bank 各取一个权重，广播给两个行的数据通路。每次计算一个 `2×8` 输出 tile，按 64 个输入通道累加；32 个 tile 构成一对完整输出行。99 行拆为 49 对加最后单行。`PIPE_MUL=0/1` 决定乘积是否寄存；`RESULT_BUFFERS=1/2` 分别提供串行计算—输出对照和双缓冲重叠候选。非法参数在 elaboration 阶段拒绝。

X 按原始行号奇偶分为 3200×16、3136×16 两个独立同步 bank，装载顺序仍为原始行优先。W 为 8 个 2048×16 bank，bias 为 8 个 32×40 bank，均在各自 generate 作用域中独立声明。W bank 号为 `c % 8`，地址为 `k*32+c/8`；bias 对应相同列 bank。每 tile 只在 k=0 读一次 bias，供两行共用。

第 98 行的第二行 X 读、乘积寄存、累加、结果快照和 SRAM 写均禁用，第二行乘法器的 X 输入置零。最终只产生 256 个输出，未读取或输出虚构第 99 行。这个门控证明无效计算被禁用；它不直接证明指定工艺下的动态功耗数值。

## 41 位精确运算和串行结果写入

任意合法 signed16 乘积绝对值不大于 `2^30`，任意 64 项部分和绝对值不大于 `2^36`，signed40 bias 绝对值不大于 `2^39`，因此任意累加中间值满足 `|sum| <= 2^39+2^36 < 2^40`。有符号 41 位范围足够。内部 accumulator、快照、结果 SRAM 和输出队列使用 41 位；接口输出明确符号扩展至 48 位，保持 `fixed16_acc48_v1` 逐位语义，没有中间舍入、饱和或丢失有效位。数值位宽变化须由全矩阵和极值向量回归核对。

每 tile 最后乘积提交后，下一拍将 16 个 accumulator 捕获至 16×41 位快照寄存器。后台写入器在接下来的 16 拍将快照逐字写入一个 512×41 位结果 RAM，地址为 `row_in_pair*256+block*8+lane`；同时下一 tile 开始其 64 拍读取和计算。下一次快照早于当前快照写完是不可能的：相邻快照间隔为 66 或 67 拍，大于最多 16 拍写出时间。最后单行每 tile 只写 8 字。

末 tile 的写入必须排空，才将该结果缓冲标为 full，避免未写完就被输出端读取。一个 buffer 在 full 后由输出端持有，直到该行对最后一个外部握手完成才释放。单缓冲等待这个释放事件再开始下一行对；双缓冲允许计算下一对行与输出上一对行重叠。若两个 buffer 都占用，计算停在 `C_WAIT`，不会覆盖结果。结果 RAM 没有复位或清零，只有所有权与有效位复位。

曾评估的每 buffer 16 个 32×41 浅 bank 虽能一拍并行写入，但按最小 128×16 宏填充时每 buffer 需 12 KiB，双 buffer 为 24 KiB。当前实现采用上述快照加单 RAM 串行写，避免这项容量浪费；它也增加了快照寄存器、写指针和数据选择器，实际面积仍需映射后比较。

## 输出和控制契约

输出严格按 `r*256+c` 递增。结果 RAM 为同步读，其返回数据经带地址标签的两项预取队列送出；输出索引、数据和 last 在 valid 且不 ready 时保持不变。发读条件为 `队列占用 + 在途返回 - 本拍输出握手 < 2`，因此返回数据有预留位置。无回压时，在初始读取延迟之后每拍输出一字。输出回压不会反向覆盖结果 RAM，释放 buffer 以实际最后字握手为准。

端口与 banked 候选相同。新任务仍需按各 kind 顺序接收全部 6336 个 X、16384 个 W 和 256 个 bias；busy 时不接受 load，未完成装载时不允许 start。非法装载置 sticky error，复位恢复；开始与结束不隐式复用旧参数。done 仅在全任务最后一个输出握手的时钟沿产生一拍脉冲。`core_cycles` 从 start 接受后的第一执行拍计到最后输出接受拍，包含所有内部等待和输出回压，饱和而不回绕；它不含外部装载，也不是比赛完整任务时间。

复位撤销 active、所有 SRAM full、读取/乘积流水有效位、writer_active 和队列占用，终止在途任务；payload RAM、accumulator、快照和队列 payload 不复位。复位之后必须重新完整装载，不能依据旧 SRAM 字节宣称任务就绪。

## 可复核周期和活动计数

令 `P=PIPE_MUL`，每 tile 为 64 拍 issue、`1+P` 拍 drain、1 拍快照，即 `66+P` 拍。一对行的 32 tile 为 `T=32*(66+P)` 拍；前 49 对额外末尾 flush 16 拍，最后单行 flush 8 拍。buffer 发布之后，第一字最早在第 3 拍握手，末字在 `word_count+2` 拍握手。开始下一行对需要 1 拍 C_WAIT 调度。

| 配置 | 无回压核心周期推导 | P=0 | P=1 |
|---|---|---:|---:|
| 单结果缓冲 | `50*T + 49*(16+512+2+1) + 8+256+2` | 131885 | 133485 |
| 双结果缓冲 | `50*T + 49*(16+1) + 8+256+2` | 106699 | 108299 |

双缓冲公式成立因为正常一对行的输出 514 拍小于下一对行计算加 flush 的 2128/2160 拍；最后只需追加最后单行的 258 拍输出排空。回压可与计算重叠，不能沿用“无回压周期 + 所有输出停顿拍数”的等式，应读取实测周期及 buffer 等待。

| 每任务计数 | 本实现 | 同 16 MAC 的单行×16列 banked |
|---|---:|---:|
| 有效 MAC 次数 | 1,622,016 | 1,622,016 |
| X 读字数 | 202,752 | 101,376 |
| W 读字数 | 819,200 | 1,622,016 |
| bias 读字数 | 12,800 | 25,344 |
| 新结果 RAM 写/读字数 | 各 25,344 | 0 |
| 外部输出握手 | 25,344 | 25,344 |

权重和 bias 逻辑读取减少约 49.495%，同时 X 读取增加一倍，并增加结果 RAM 和快照活动。只有指定库、宏及完整窗口下的功耗分析才能判断净能耗收益；不能把 W 读取减少比例写成整机能耗减少比例。

供 testbench 和活动分析使用的层次信号：

- `x0_rd_en`、`x1_rd_en` 每次各计一个 X 字；`w_rd_en` 每次计 8 个 W 字，`b_rd_en` 每次计 8 个 bias 字。
- `row1_mac_en` 为第二行有效累加；`pair_index==49` 时必须为 0。
- `result_capture_en` 是每 tile 快照事件，通常 16 字、最后单行 8 字；`result_wr_en` 是后台 SRAM **单字**写使能，`result_rd_en` 是单字同步读使能。
- `compute_active` 包括 C_RUN、C_DRAIN、C_STORE、C_FLUSH；`compute_wait_buffer` 表示在 C_WAIT 且目标 buffer 仍 full。
- `result_full`、`compute_buffer`、`output_buffer` 表示所有权；`rd_pending`、`q_count` 表示读流水和队列占用。

## SRAM 核算边界

逻辑 RAM 总量为 `373760 + RESULT_BUFFERS*20992` bit，即一缓冲 48.1875 KiB、双缓冲 50.75 KiB。逻辑 memory 对象数为 `18+RESULT_BUFFERS`：2 个 X、8 个 W、8 个 bias，加结果缓冲。这里不包括 accumulator、快照、读寄存器和队列寄存器，它们进入标准单元面积。

仅按已知 128/1024/4096 深度、16 位宽宏容量作一份候选填充清单：X 使用 `6×1024 + 2×128` 字；W 使用 `16×1024` 字；bias 使用 `24×128` 字；每个结果缓冲使用 `12×128` 字（4 个深度页 × 3 个宽度切片）。单/双缓冲宏容量为 53.5/56.5 KiB，宏数量为 60/72。双缓冲面积符号式为 `50*a128 + 22*a1024`；这只是一种容量满足的组合，宏片选和地址控制尚需实际包装。

这些不是实际宏实例化、布图或面积证据。512×41 也可能采用其它宏组合；最小容量未必最小物理面积。正式严格 `<2.25 mm²` 必须同时核算新增核心（含快照/队列）、新增接口、所有内部 SRAM 宏和相关控制。实际宏端口、时序、保持、输出稳定规则及功耗模型仍需平台资料。当前读写所有权分时，可尝试单端口宏映射，但仅凭推断数组不能宣称已经完成映射。

## 验证入口与验收范围

新 testbench 和独立 runner 为 `sim/tb_rowpair_benchmark.sv`、`scripts/verify/run_rowpair_benchmark.py`。至少覆盖四种 P/buffer 组合、完整 99×256 输出、12 个独立层任务、极值/随机/真实权重、随机回压与首输出长期回压、两个 buffer 耗尽、busy 装载拒绝、复位中断、奇数尾行和输出无重复/丢失。无回压周期、实际读写次数和结果保存量都应与上述公式逐项核对。

结构综合应确认结果 RAM 为独立同步读对象，所有 payload 无复位，未展开成多写口浅 bank；41 位运算须由前后位级对照验证。结构 PASS 不替代指定库下 150 MHz 的 setup/hold/约束覆盖、严格总面积门槛和完整窗口能量测量。
