## 候选和筛选依据

| 候选 | 机制 | 当前判定 |
|---|---|---|
| A：8 lane 快照后提前 POP | 保持最少 18 笔事务，提前释放槽位 | 同条件 Icarus 单层正确但有效周期 586,295，比原版增加 2；筛除，不送综合 |
| B：最后 lane 读响应同时 POP | 新增 `0x1a0` 别名，保留旧窗口/POP；最少 18→17 笔事务 | 12 层整机与全部输出通过，含清空周期减少 2.8258%；选为交付候选 |
| 减少额外状态轮询 | 只减少空读，同时保持有界轮询、组号校验 | 需先证明延迟/退避能减少总周期，不能删除校验 |
| POP 同拍 launch | 减少满槽释放后一拍调度空洞 | 需真实 trace 证据；可能被 bias 等待遮住 |
| 加深 FIFO | 多暂存结果以吸收突发停顿 | 持续消费带宽不足时不消除事务，暂不实施 |
| 合并 SEND/WAIT 状态 | 尝试同拍发下一命令 | 当前单槽 BIU CUT_READY 限制接续，缺乏整机收益依据，暂不实施 |
| 缩减调用/描述符开销 | 保持非零返回检查，缩短完成至下次请求间隙 | 先测量，不删除错误检查或强制 rd=x0 |

A 的清空周期仍为 198,403，合计 784,698。FIFO 满等待从 154,639 降至 150,087，计算/写回重叠从 151,767 升至 154,638，但事务数与轮询数不变，整任务没有受益。这说明不能用单个等待计数下降代替全任务收益。原件为 `early-pop-icarus-task0/`，严格来源差异对照为 `early-pop-comparison.json`（均位于 `build/writeback-20261108/`）；源码补丁保存为 `early-pop-parent.patch` 和 `early-pop-submodule.patch`。

## 仿真启动问题与处理

原 TB 采用初始 `rst_n=0` 再释放。Verilator 二态启动下，门控时钟域的标签 FIFO 未获得四态模拟器的初始 X→0 异步复位事件；首请求前写/读指针为 `0000`，应为 `0001`，导致 completion 无有效标签而卡住。基线与候选、多种合法 rd 分配均复现；原断言及时失败。

`--x-initial-edge` 单变量试验在本机 Verilator 5.032 触发运行时 timing 错误，未用作修复。仅通过 **外部 pad 引脚**进行一次显式预热后重新拉低复位，已在相同 RTL 和原断言下完成单层；删去该脉冲则重新失败。没有修改 E203 核内 RTL、force 内部状态、放松超时或删除断言。

runner 提供显式 `--startup-profile external-reset`，保持默认 historical 不变；只供 Verilator 开发使用，记录协议版本、120 ns 外部低脉冲、预热 watchdog、禁止预热期任何 source/NICE/MMIO/shared 事务，以及实际复位观测。完整比较将要求两组使用同一 startup profile、时钟、工具及固件。

失败和最小复现保存在 `build/writeback-20261108/diagnostics/verilator-fifo/`，CPU 小夹具交叉检查在 `build/writeback-20261108/checks/completion-fixture/`。诊断 TB 的临时探针留在 build 目录，未进入生产测量入口。
