## 2. 基线与实施边界

| 指标 | 已测服务器基线 |
| --- | ---: |
| 工作负载 | 单个静音样本夹具的 12 个独立 FFN1 任务 |
| 每任务计算 | `Y[99,256] = X[99,64] × W[64,256] + bias[256]` |
| layer0 TB 周期 | 2,368,078 |
| layer1–11 TB 周期 | 各 2,368,074 |
| 12 个计时窗口总周期 | **28,416,892** |
| 条件 @150 MHz 平均延迟 / 吞吐 | 15.787162 ms / 63.342606 任务/s |
| MAC 活跃占比 | 8.561893% |
| 阶段占比 | bias 33.17%、结果回读/写回 33.97%、W 13.38%、X 5.13%、计算 9.23%、其他 5.12% |

硬件保持 8 PE、signed16 X/W、signed40 bias、signed48 Y。输出逐字结果、W bank 映射、行优先 Y 地址递增、完整写回退休后 ACK、W1C/START/超时/fence 语义保持一致。每任务重新装载 W 和各自输入，中间不复位 SoC。当前硬件仅有一行 X 缓冲和 8 个 bias 槽；沿用 row→group 顺序。

主比较指标为首次共享输入/参数读接受到最后 Y 写响应退休的总周期。缓存复制和每任务准备成本放入此窗口。行为共享 RAM、全局 modulo-7 背压、ITCM 装载、任务数及排除项沿用原定义。六阶段包含软件与总线间隙，DTCM 访问不触发阶段切换，因此阶段变化只辅助归因。

150 MHz 始终标为条件换算。该夹具用于开发平台性能比较，不代表完整 encoder、官方评测成绩或样本集精度；本轮不新增面积、功耗和 CPU-only 加速比结论。

## 3. E0：先让验证器认识新的调度

当前两处实现都把每任务共享读锁定为 73,408：`tools/scripts/e203_soc.py:check_performance()` 和 `tools/scripts/xu_perf_report.py:summarize()`。直接实现缓存会被正确拒绝。先增加显式固件调度配置，使编译选择、运行元数据、计数验证和性能汇总使用同一身份。

建议配置名为 `baseline` 与 `bias-dtcm`，另用独立字段记录编译优化选项，避免与 `server_accept.py` 已有 `profile=vcs-platform` 混淆。旧无调度字段的报告按历史 `baseline` 处理；未知配置、计数与配置不匹配均失败。公共工作量与各配置事务契约集中定义，运行器与报告器共享使用。

| X 共享读 | 6,336 | 6,336 |
| bias 共享读 | 50,688 | 512 |
| 共享读总计 | **73,408** | **23,232** |
| 共享 Y 写 | 50,688 | 50,688 |
| START / done | 各 3,168 | 各 3,168 |

保留有序 TASK_PASS/PERF_TASK/SOC_PASS、完整结果计数、六阶段求和、MAC/busy 活动和失败日志检查。MMIO 轮询读次数可随软件变化，按实际结果记录；不能将其固定成基线的 69,696。缓存实验的 bias MMIO 写仍为 **76,032 次**，不能将 bias 阶段整体当成可消除时间。

完成条件：历史 baseline 报告仍能复算为 28,416,892 周期；新配置接受 23,232 读，旧配置接受 73,408 读；未知配置、两者错配、漏层/重复层、错误 MAC 数、错误写回数和阶段和错误均有失败用例。只改验证配置时，原固件执行结果保持一致。

## 4. E1：独立实现每任务 bias 的 DTCM 缓存

修改入口为 `tests/e203/firmware/accel.c`，按固件调度配置选择原路径或缓存路径。

1. 使用 **512 个 `uint32_t` 原始字，共 2,048 字节**保存 256 个 bias 的低/高字，保持原来的 signed40 位模式；源指针保留 `const volatile`，MMIO 和 Y 访问保留 `volatile`。
2. 在 `accel_linear()` 内，**完整 W 装载之后、首行 X 装载之前**，每任务从共享 bias 区复制这 512 个字。此位置保持原首次共享读起点，复制读取与全部 DTCM 写入均纳入计时。基线窗口外的首个 W_BANK/W_ADDR 两笔写也继续位于窗口外。
3. 后续保持原 row/group/bank 调度，从普通 DTCM 缓存读取原始字并写入现有 8 个 bias 寄存器。每任务覆盖全部缓存内容，不依赖上次任务或静态夹具常量。
4. 保留 RESULT_HI 的 signed16→signed32 扩展与完整输出写回。DTCM 使用现有 BSS 或栈空间，保留启动不复制初始化 `.data` 的链接约束；记录 BSS、栈与剩余空间。

E1 使用服务器原 SiFive 工具链与 **`-Os`**，只改变缓存，不同时展开循环或调整优化等级。程序选择与验证配置匹配；baseline 路径仍可独立运行。

完成条件：先通过至少 **2 个连续 synthetic 任务**（各层 bias 不同，可暴露陈旧缓存），再通过 real1；缓存 profile 的共享读精确为 23,232，全部整数结果正确。随后在服务器 VCS 完成 real12，记录完整周期与身份，才能宣布性能收益。

## 6. 实验与验证顺序

1. **复核环境与基线**：核对执行文件哈希、E203 gitlink、夹具、编译选项和工具版本。已有完整原始日志可验证时直接使用；若文件身份或环境变动，先在独立输出目录重跑 baseline。基线不一致先定位原因。
2. **主机契约检查**：运行 `python3 -m unittest discover -s tests/e203 -v`。本轮新增配置、反例、历史兼容和编译选择的检查应全部通过。
3. **候选快速检查**：本机可先用 Verilator 跑 synthetic2/real1 发现错误，但本机 GCC14 周期只作本机比较。每个独立候选至少有正确性回放；组合或编译配置改变后也应检查。
4. **服务器 A/B**：用同一 SiFive GCC-Metal 10.2.0-2020.12.8 CentOS6 子集、VCS Q-2020.03-SP2-6 和相同激励，对值得保留的候选运行 real12。各候选输出目录独立，每次 `--out` 尚不存在。串行运行会改 `make install` 的任务，避免安装目录竞争。
5. **最终验收**：胜出组合执行服务器 `server_accept.py --sim vcs`，沿用完整 host/numeric/向量/doctor/基础 SoC/synthetic1/real12 范围，并补 synthetic2 连续缓存检查。若验收入口增加调度选项，确保所有子步骤使用正确配置。

验收入口不会自动生成性能摘要。验收通过后，显式运行以下命令，其中 `xu_accept_out` 为本次新验收目录，摘要文件须尚不存在：

```bash
python3 tools/scripts/xu_perf_report.py \
  --result "$xu_accept_out/real12/result.json" --frequency-mhz 150 \
  --out "$xu_accept_out/xu-performance.json"
```

原命令结构见 [测量方法](xu-performance-method.md#服务器复现与结果保存)。本文提出的新 CLI 配置尚未实现，接手 session 应先实现并以 `--help` 核对实际参数，再写最终复现命令。

## 7. 最终验收与交付

功能必须满足：真实 12 层共 **304,128 个结果、608,256 次输出写字**逐字通过；所有层有序完成，最终 ACK/提交正确；配置对应的事务数正确；六阶段覆盖窗口；计算工作量保持不变；缓存每层刷新。修改范围核对确认 RTL、ABI、向量、数值模型、测试时钟和背压与基线一致。

有效性能优化要求：在同一服务器交叉工具链与同口径下，12 个窗口总周期 **严格低于 28,416,892**。报告每层差异、总加速比 `baseline_total / candidate_total`、150 MHz 条件换算、MAC 活跃占比、阶段/事务数，以及 ELF/ITCM/BSS/栈空间变化。不同交叉编译器的结果分开列。没有收益时交付实测结论，不能预告或补造倍率。

交付到带 `xu` 标识的功能分支，提交实现、必要测试和新增结果文档，不改写已有基线证据。报告至少包含：

- 每个实验的父提交、改动、调度/编译配置、结果、选择或放弃原因。
- baseline 与最终版本的逐层周期、总周期、加速比及计数比较表。
- 完整复现命令、工具版本、RTL/TB/固件/运行器/向量哈希、原始日志位置与 SHA256。
- 最终验收实跑项目、失败及未运行项目；源代码 diff 的边界说明。
- 若传输受限，沿用屏幕证据 + 完整 SHA256 核对的观测收据，区分原始文件与本地派生汇总。

建议分开提交：E0 验证配置 → E1 bias 缓存 → E2/E3 胜出驱动优化 → 实测报告。只有实际通过的范围记 PASS；最终工作树保持可审查。
