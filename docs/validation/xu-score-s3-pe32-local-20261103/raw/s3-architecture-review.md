## Confirmed architecture and capacity

Implementation plan is one physical32-lane engine, one X row, one complete W array and one256×40 bias cache. Existing8-lane generated modules remain in the repository for default compatibility, but must not be instantiated alongside the new32-lane engine in the candidate SoC. New wrapper is `xu_pe32_icb_slave`; actual selection must be frozen and verified by hierarchy/capability and simulator identity.

W logical shape stays256 columns ×64 K ×16bit =32768 bytes. New32 independent banks each contain512 logical16bit words. One actual RAMSP1024X16 per bank yields32 W macros and65536 physical bytes; A[9] must be zero and upper512 rows are padding, not extra logical capacity. Together with320 fixed SoC macros (256 shared,32 ITCM,32 DTCM), expected ordinary1024 macro count is352, instead of baseline336. This is a structural count, not an area estimate. Candidate source guards, clear/activity observer, inventory and power mapping must explicitly support this geometry rather than reuse old336 assertions or baseline SAIF.

Old `(bank8=b, addr11=a)` writes map to `bank32=((a>>6)&3)*8+b`, `addr9=((a>>8)&7)*64+(a&63)`. This is a bijection over all8×2048 old locations onto32×512 new locations. Independent exhaustive arithmetic checked all16384 pairs and all16384 K-major stream cursor positions, including `(7,2047)->(31,511)`; see `s3-remap-exhaustive.json`. This proves the proposed arithmetic, not its eventual RTL implementation. Keeping the old3bit bank/11bit address ports and remapping centrally lets old scalar/packed upload images remain exact. PACK starts even, so a single pair never crosses bank7→0; scalar cursor7→8 and separate PACK cursor6→8 commands still exercise the crucial column-subgroup carry.

Old manual group g∈0..31 selects wide group `g>>2` and old8-lane subblock `g&3`. Uncached8 biases map into that subblock; cached biases use full32-vector lookup for the wide group and the same subblock. Flat bias write/read addresses retain all8 bits, byte masks, signed40 values and no duplicate full cache. The old group5, bank3, addr11 and result-index3 readback/masking behavior must remain exact.

## Issues identified and implementation responses

1. **Actual lane work must stay observable.** Initial plan ran all32 PEs for each old8-lane group and sliced8 outputs. That would perform6488064 physical lane MACs per old task for1622016 useful MACs, while old `mac_fire*8` would hide the extra work. Implementer accepted explicit per-lane init/accumulate masks: old manual/cache/auto activates exactly the corresponding8 lanes; wide mode activates all32. W bank read enables follow the mask without handmade clock gates. An added PE_TASK must sum actual downstream PE enable popcount, distinguish physical32 lanes from active lanes and require1622016 actual lane MACs per complete task. Clock pins of inactive lanes still contribute physical overhead in the eventual power run; no zero-power inference.
2. **Last manual results require a captured slice selector.** Existing result registers hold the last completed8 results independently of a later GROUP write. New32-vector output cannot select using live `group&3`: e.g. group3 finishes, software writes group4 before START, and a result read must still return group3. Reviewer reported this to implementer; capture the launch/result subgroup with the result. FIFO entries likewise must retain the corresponding produced-group metadata and not follow the next producer group. Requires a directed test, pending source review.
3. **One physical candidate for every firmware control.** If a preprocessor define selects the new wrapper, architectural variant must be independent of firmware schedule and enter compile argv/build-cache/result identity. Wide real12 and old autogroup-control real12 must share the same PE32 top and simulator SHA. Compiling PE32 only for wide firmware and falling back to old8PE for control is invalid. Default old-wrapper tests are supplementary; direct legacy compatibility must instantiate the new wrapper itself. Reported to implementer, pending source.

## Additive ABI and ownership conditions

Planned old capability words and old080..0bc manual/100..13c auto windows remain exact. New capability07c=`58332001`; START/STATUS/POP0d0/0d4/0d8 and new32-lane result window200..2fc do not overlap the existing S2c ABI. This candidate starts from S2c, so07c does not advertise S2d double buffering. `0x2f8/0x2fc` must return lane31 LO/zero-extended HI; lane16 must not alias lane0, and0x300 must not wrap into the32-lane window. Invalid masks/data, unaligned new window accesses, empty heads and wrong-mode POP/window accesses need explicit defined behavior and held response tests. Existing unimplemented-address semantics should not change accidentally.

Successful START selects old-auto32group or wide8group mode for the complete row through final POP response retirement. Active/pending starts and the complete row lease exclude all operand/config writes, including delayed scalar and packed write strobes. Cache must already be enabled as required by the contract; no cross-task parameter reuse or pre-window staging. Old/new START when manual/buffered work is pending must reject without acquiring ownership. Mode change cannot let a response retire against a different FIFO head.

FIFO remains two entries of32×48 values (3072 result bits), not two independently duplicated engines/stores. A launch reserves capacity. Enqueue/POP simultaneous events conserve count. Head data/tag stay stable under held reads and stalled POP response. Only a successful explicit mode-correct POP response retirement releases an entry. Same-edge POP retirement plus read/another POP must not consume the replacement head; error response metadata must not inherit POP. Old row retirement ends at32 POPs; new wide ends at8 POPs. Counter widths must represent the terminal32 or8 value instead of wrapping to0. A complete wide task has99 row STARTs and792 POPs, with row tags/groups checked by firmware or directed TB.
