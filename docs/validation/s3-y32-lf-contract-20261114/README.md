# LF 外部接口合同 v1：团队工程条件与验收

本目录记录原 1064 修复候选的**新增团队接口合同**及其独立验证。本合同于 2026-11-14 经用户授权制定，针对 BOOTROM、DWAKEUP、ERST 的外部激励条件；不是组委会发布的板级规格，也不是对原未知检查的官方豁免。当前没有实际板级输入来源资料，板上控制器能否提供该条件仍待确认。

原结果及其原 SDC 保持独立：原最终映射 `d83acb49caec51aabc66d8ad61b8784294bebe26c5458aa0b095f9d12a2ae0d1`，RTL 子提交 `5470c5650f2d11d16e7c52cc96626d21030a3973`；原报告 0 项数值违例、0 项电气违例、4 项 unknown。新合同的 SDC、工具、执行收据及原始报告必须另存，本轮新合同原生采集已返回 0 数值违例、0 电气违例、0 unknown；完整身份与外部源数值路径仍在独立复核，新合同 CPU12 尚未完成，不能仅以汇总归零宣布最终验收完成。

## 合同为什么合理

平台 `sirv_DeglitchShiftRegister` 使用 LF 上升沿依次更新 `T_8`、`T_9`、`sync`、`last` 四级寄存器，输出为 `sync & last`，其代码明确这些级不依赖 reset 初始化。BOOTROM 在启动前稳定八次有效采样并一直保持，可以让四级状态得到真实的已知输入；当前测试台要求 BOOTROM 从 time 0 已知且全程不变，不支持启动中切换 strap；SDC 仍给该输入 LF 下降沿后 1–2 ns 的保守到达包络，以保留原检查，不以 case analysis 删除检查。此到达包络不是许可仿真中切换 strap 的操作。DWAKEUP 每个电平保持四个完整 LF 周期且至少四次有效采样，为该去毛刺结构提供持续输入；在下降沿后 1–2 ns 改变，为下一个上升采样沿留下约半个 LF 周期。

ERST 为低有效外部复位，平台将其反相后异步置位 PMU 复位捕获寄存器及复位 catch。合同保留任意相位断言，要求低脉宽及有效采样数，并限制撤销时刻；这是一项环境义务，不是由现有片内同步结构自动保证的板级能力。初始未知值、停钟时经过的墙钟时间及非法窄脉冲均不能替代有效采样。

BOOTROM/DWAKEUP/ERST 的名称不能单独证明它们可任意异步变化而不需要时序分析。本合同接受的是受约束的外部控制源；来源原本异步时，外部控制器必须真实完成相位安排。尚无该控制器的硬件实证，功能测试台只能验证数字合同和片内行为。

## 统一定义与数值

- HF 目标仍为 150 MHz，工程 SDC 周期仍为 6.666666667 ns。
- LF 仍为 32.768 kHz，周期 `T_LF = 30517.578125 ns`；半周期为 15258.7890625 ns。
- `4 T_LF = 122070.3125 ns`；`8 T_LF = 244140.625 ns`。
- 有效 LF 采样以外部环境提供合法 LF 波形为前提。本回归使用固定频率及占空比的已知时钟，并测试规定的停钟场景；pad 监控器统计实际上升沿，不独立验证任意时钟的周期、占空比、X/Z 或异常窄脉冲。异常时钟须由外部环境另行排除。
- 下降沿后 1–2 ns 指 pad 在顶层接口的实际逻辑变化时刻；区间两端包含。它不是源时钟抖动、线路延迟或 STA 结果的别名。
- 低脉宽及保持周期均从 pad 上一次实际变化时刻计算，除持续时间门槛外，还必须满足独立有效采样次数门槛。

| 接口 | 外部源义务 | 初始化与停钟规则 |
|---|---|---|
| BOOTROM strap，`io_pads_bootrom_n_i_ival` | 从测试 time 0／有效上电初始化起为已知 0 或 1；全程保持不变，首次 ERST 撤销前至少经过 8 次有效 LF 上升采样。当前监控器拒绝启动阶段或运行阶段的任何 strap 切换。 | 不用 reset 将 strap 的未知初态视作已知；LF 暂停时仍保持。实际板级上电后的稳定起点由外部控制器保证，不能仅靠仿真 time 0 赋值证明。 |
| DWAKEUP，`io_pads_aon_pmu_dwakeup_n_i_ival` | 每次上升或下降变化均在 LF 下降沿后 1–2 ns；每个高、低电平保持至少 4 T_LF，且至少经过 4 次有效 LF 上升采样。 | 初始电平为已知；LF 停止时保持电平，暂停不能补足采样次数；恢复后达到保持门槛再变化。合同不覆盖依靠停转 LF 时改变该 pad 来唤醒的外部模式。 |
| ERST，`io_pads_aon_erst_n_i_ival` | 允许任意相位由高变低断言；每次保持低至少 8 T_LF，且至少 8 次有效 LF 上升采样；只在 LF 下降沿后 1–2 ns 由低变高撤销。 | 初始化为已知低；LF 停止时可再次断言，但不可撤销；恢复后必须满足实际低脉宽、有效采样次数和合法撤销边沿。 |

顶层实际 port 拼写应由新 SDC 和实际 PPA top 精确核对，不能用 wrapper 内部短名称误选其它信号。若外部对 BOOTROM 的合法取值有两种模式，应分别验证；本合同不自行指定启动地址模式。

DWAKEUP 的四周期门槛与四样本门槛同时适用；ERST 的八周期与八样本亦同时适用。只满足其中一个不能通过合同。停钟不属于正常任务计时条件；重启后的合法波形由测试时钟发生器保证，pad 监控器本身不检测任意恢复毛刺；该边界须在板级环境中另行保证。

## 与官方要求的关系

两份已提供官方文件未给出这三路 pad 的脉宽、相位或异步例外清单。官方确有 150 MHz 目标、32.768 kHz 常开域时钟、工程时序完整性及不得隐藏违例的要求；答疑允许选择有依据并完整披露的合理工作条件。以上支持提交清晰的工程假设与对应 SDC，不能推导为组委会已经批准本合同或允许任意屏蔽 AON 检查。

## SDC 与验证边界

新合同应直接建模真实边沿关系：DWAKEUP 双极性变化及 ERST 撤销边相对 LF 下降沿，而 ERST 异步断言须保留其独立语义。不得把两条 ERST 边都标成定相输入后，宣称仍覆盖任意相位断言。本轮 BOOTROM 仍保留 setup 检查，使用 LF 下降沿后 1–2 ns 的保守到达包络分析，不采用 case analysis 或常量传播使 unknown 消失。ERST 断言边暂保留旧 HF envelope 作遗留分析模型；该模型不约束实际任意相位断言，亦不证明异步断言的物理安全。本轮数字验证覆盖合同脉宽及功能恢复；任意相位断言的物理保证、MTBF 或板级实现不由这些证据证明。

除明确列出的三路输入合同外，HF、LF、JTAG、原有其它输入/输出预算、uncertainty、transition、gating、负载、原库与当前映射身份均应保持。所有变更须有逐命令差异清单。禁止用 broad false path、multicycle、异步时钟组或 ideal network 代替合同实现；本轮目标是原四项取得明确原生数值 MET；其它检查保持身份、状态及原因，若出现删除、disabled、no_clock、新 unknown 或新增违例，则本轮严格门禁拒绝。

验收应同时提供以下证据：

1. 新合同 SDC 的原件、SHA256、与原 SDC 的精确差异，以及所选 mapped、标准单元库、SRAM 库和原生工具身份。
2. 三路 pad 的正常激励，以及错边沿、短脉冲、BOOTROM 改变、X/Z、停钟/恢复等拒绝用例；拒绝必须来自实际监控器，不能仅检查输入参数。
3. 同一最终 mapped 的新进程完整 STA、所有检查汇总及完整身份明细、独立工具日志和 PTE-052 上下文；数字与电气违例、全部 untested 原因完整报告。
4. 原 4 项 unknown 的逐身份账本：原状态、新状态、精确外部源及极性的原生 required/slack，以及其它检查身份、状态和原因的严格等集证明。四项必须取得明确数值 MET；数量归零、删除检查、变成 `constant_disabled` 均不能通过本轮验收。PMU 必须读 ERST pad 上升撤销边的原生上下文，不能拿 LF 内部 watchdog 路径替代。
5. 当前 RTL 的 CPU 完整任务回归，真实物理 clear、源装载、完整 Y32 写回与吞吐边界保持；如重启 prelude 变长，与任务窗口明确分列。

已有 `unknown_checks.py` 固定原合同、原 SDC 和原 exact4 身份。它应继续如实拒绝将新合同文件冒充旧合同闭合证据；新合同验收应单独声明合同版本和覆盖差异，不应删掉原门禁或修改冻结原件。
