# xu 首版性能基线 — 2026-11-02

服务器 VCS 重新执行 **12 个真实 FFN1 任务并全部通过**，检查 304,128 个 signed48 结果和 608,256 次 32 位写字。加入旁路性能计数后，每层总周期与 2026-11-01 验收完全一致；固件镜像、计算 RTL 和向量哈希也一致。8 PE、数值格式、MMIO ABI 与固件未修改。

这是单个静音样本夹具的 12 个独立 FFN1 任务，**150 MHz 为条件换算，尚未据此证明物理时序闭合**。每任务 `99×64×256 = 1,622,016 MAC`，1 MAC 按 2 ops 计。共享行为 RAM 每 7 周期注入一次命令背压。计时从首次共享输入/参数读接受到最后输出写响应退休，包含 CPU/MMIO/计算/等待/写回；排除 TB/ITCM 预装载和任务间主机换数据。任务吞吐以这些计时窗口为分母，不能解释为完整 encoder 或音频样本吞吐。

## 时间花在哪里

下表为全部 12 任务合计；六个阶段互斥并恰好覆盖总周期。阶段包括其间的 CPU 指令和总线间隙，不能解释为纯传输延迟。

| 阶段 | 合计周期 | 占比 |
| --- | ---: | ---: |
| 权重装载 | 3,801,373 | 13.38% |
| 输入装载 | 1,457,688 | 5.13% |
| bias 装载 | 9,425,593 | 33.17% |
| 计算区间 | 2,623,104 | 9.23% |
| 结果回读与写回 | 9,653,690 | 33.97% |
| 其他软件/控制间隙 | 1,455,444 | 5.12% |

装载与结果搬运区间合计 **85.65%**。计算区间占约 9.23%，每组仅 69 拍，其中 busy 68 拍、真正执行 8 个 MAC 的有效拍为 64。优先排查驱动的 MMIO 装载和结果回读路径，比单独压缩 MAC 控制拍数更有依据；本轮未做优化或归因实验。

每任务观测到：3,168 次 START 和 done、202,752 个 MAC 有效拍、215,424 个 busy 拍、69,696 次 MMIO 读、156,326 次 MMIO 写、73,408 次共享读、50,688 次共享写。共享读包括 W 16,384、X 6,336 和重复 bias 读 50,688。共享端点受阻拍数为 layer0 的 24,011、其余层各 24,007；MMIO 端点握手受阻拍数均为 0。这些旁路活动/受阻计数与六阶段重叠，不能再相加，且 0 MMIO stall 不代表 CPU 发起 MMIO 没有开销。

## 旧综合报告与本轮边界

旧 `xu-core-ss.tcl` 只综合 `LinearComputeCore`，使用 SS/0.99V/125°C 标准单元和 SRAM 库、6.667 ns 时钟。报告中相关路径显示 6.62 ns 到达、约 0.00 ns slack（[页1](old-dc-timing-page1.png)、[页2](old-dc-timing-page2.png)、[Tcl](old-dc-tcl.png)）。其 MMIO/SoC 接入范围、IO 约束、全部源集与宏包装的身份未核实完整，未用于声称完整平台 150 MHz 闭合或完整增量面积。

本轮没有新的面积/功耗结果、CPU-only 对照加速比、完整 encoder 吞吐或官方评测成绩；原版 `--full`/Chisel 的验收范围仍单列。上述吞吐数值仅为测得周期在目标频率下的换算。
