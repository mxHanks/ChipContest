## 对照与共同约束

本轮唯一性能对照为 read-pop 主仓 `562a8c91a42ba96c584c78c475fb972e6ac11d49` / E203 `6e2ec8995c92f97a0b1c45a3652f902ad43ef8e1`，不是上一轮的 18 事务版本。已通过的 12 层：payload 6,769,416、clear 2,380,836、两者之和 9,150,252 周期；每层 payload 564,118、clear 198,403。

该对照中 writeback 为 297,795 / 564,118，约 **52.8%**。此阶段包括状态查询、结果读取、总线等待和共享写，不代表纯共享内存写服务时间。

保持 Y32 数值与原 drain8 编码兼容；不修改 E203 LSU/BIU/在途配置。新指令采用独立可选编码，旧指令含义不变。参数清空、所有输出黄金值、最后 Y 写响应窗口、OITF/rd 退休、单在途、背压和错误后中止均保留。接口实验只能增加经过审查的端口连线，不能修改 CPU 控制逻辑。

所有方向以相同夹具、RV GCC 14.2、Verilator 5.032 `--assert`、150 MHz 刺激及显式 `external-reset` 做开发周期比较。新 RTL、固件、观察器及契约的差异逐项记录；不将仿真刺激视为 STA，不将二态开发 PASS 当作 VCS/门级验收。

## 四项计划与判定

| 方向 | 要测的问题 | 实验与通过门槛 |
|---|---|---|
| 1. 内部取数通道 | 8 个结果能否不经 LSU/MMIO 往返，直接交给 NICE？ | 原子快照握手、稳定 payload/group、收齐后恰一次 POP；保持状态轮询语义，第一版公共总线最低 17→9 笔。逐 lane 内部捕获以复用 RNE，再交付完整组；记录寄存器/连线/时序风险。单元→task0→有收益才12层。 |
| 2. 减少重复状态轮询 | 额外 1,881 次查询能否减少，是否只是把必要等待搬到别处？ | 先测查询位置分布，小范围固定延迟/退避对照；poll_limit 仍按实际退休状态响应计数，不能替换为周期数或删除组号/状态检查。周期不降即筛除。 |
| 3. CPU 每组调度开销 | 完成一组到发起下一组之间有多少循环、地址计算和同步开销？ | 被动计数 completion→request 的组内/跨行间隔，核对反汇编；测试局部循环展开。每次 code 非零立即中止，保留 fence 和 memory clobber；保持每次请求/退休契约。 |
| 4. 多组连续搬运 | 一次请求完成多组能否摊薄 CPU 调度？ | 独立 drainN 编码保留 drain8；限定 row 内，精确范围/count/poll 校验，逐组检查错误、背压与所有权。先与方向1分开，用 read-pop 传输测单变量收益；请求/完成数改变须有新契约，不放松输出/POP/末响应。 |

DMA 不在本轮范围。无测量证据不扩 FIFO 或增加 PE；也不因单个等待计数降低而宣称全任务加速。
