# 64PE B 全要求核对（2026-11-13）

**结论：当前已发布64PE B不满足全部要求，不能作为合规比赛方案或正式4k task/s成绩。** 新答疑已把原先“宽口平台资格待确认”明确为不符合：平台总线、加载和共享SRAM访问必须保持32位，DMA及结果写回必须经过原有System Bus，不得用新增互连/专用装载旁路替代。同时，现有性能计时没有覆盖输入和参数开始写入共享SRAM的全过程。

本报告只读核对源码、PDF和既有实测原件；没有改生产RTL、重跑仿真/综合、访问服务器或更新GitHub。本报告不改写旧测量。旧“仿真定稿/面积选型”表示工程候选选择，不表示正式资格通过。

| 5 量化/布局/逐位 | 部分已验证 | INT16、bias40、RNE9/Y32、packed W脚本和12组逐位对照存在；官方音频到冻结B的完整评测链与误差仍需补齐。未发现B通过重新训练/微调/蒸馏改变模型。 |

## 旧数字的使用边界

- 304128输出精确一致、真实clear、逐层工作量完整：仍是旧架构的真实工程证据。
- 428915拍和约4196.64task/s：仍保留为当时定义的开发口径；**不符合新明确的完整参数装载口径，不能上报正式吞吐**。现有日志缺完整起点，不能补gap、机械翻倍或猜测一个合规吞吐。
- 面积比旧48位候选下降3.6886%：仍是同库、同接口体系下的真实比较；不代表合规接口下的新面积、官方mm²或正式面积成绩。
- “完整输出无压缩符合”：只覆盖输出存储这一条，不代表访问通路合法。

## 最小整改顺序（本次未执行）

1. **先改通路**：保留可复用的64PE、共享W/bias、41位有界数值和内部缓存思想；恢复规定32位System Bus、共享SRAM接口与原协议/既有并发能力。DMA读输入、读参数与写结果都经过规定路径；去掉新增下游旁路、64位共享并访和TB专口装载。
2. **再改装载和计时**：从每任务首个输入/参数加载请求至末输出写响应记录完整周期，涵盖全部加载、等待、CPU调度及中间gap；清空任务数据/参数缓存，保留错误、背压、复位、排空与内存可见性保证。PC读文件/一次性格式转换按答复排除；验证用输出poison和末读回另列。
3. **补官方数据入口和精度**：指定音频与checkpoint→规定前处理→各层FFN1输入→冻结B数值模型/编码/解码→性能向量。跑本B数值配置的多样本精度，准备官方600样本和官方12性能任务验收，不能直接套旧raw48评估。
4. **改后重测**：局部协议/数值，再CPU完整12任务，随后对唯一同配置版本集中综合、150MHz时序、综合后功能检查、全SoC活动/功耗/能耗和官方面积计价；补全网表和可复现交付。旧周期/面积/PT不能直接沿用。

64PE数量和41位本身无需因答疑自动退回8PE；但受32位合法搬运约束，原4k目标是否可达必须重新测量，本次不作承诺。
