## 总分选择规则

本科效率分为：

```
S_eff = 8 * T / T_max + 8 * E_min / E + 4 * A_min / A
```

T为任务/秒，E为全范围焦耳/任务，A为正式口径加速器面积；极值来自本组合格设计。单项最高分别8/8/4分。其他参赛者极值尚未知，不能预报最终得分。

若固定其他队伍参照，候选自身可能刷新极值，等价形式为：

```
8 * min(1, T / T_other_max)
+ 8 * min(1, E_other_min / E)
+ 4 * min(1, A_other_min / A)
```

比较原则：

1. 先满足资格及可复现证据，保护功能/SoC分及后续40分入口。数值10分还随误差下降而提高，不能只检查3%是否过线。
2. 每个候选冻结同一套硬件、固件、网表、约束、数值格式和活动，获得(T,E,A)。不拼接不同候选的最快周期、最低能量和最小面积。
3. 保存所有非支配候选：不存在另一合格设计同时T不低、E/A不高且至少一项严格更好。性能实验胜者保留为候选，不自动变成比赛最终提交。
4. 对有取舍的候选做对手参照范围的评分敏感性比较；未知对手时采用明确说明假设的选择，不声称数学上已达到全局最高分。
5. 创新20分按方案8、同条件对照8、答辩/贡献4组织交付。记录设计依据、独立实验、未保留项和复现方法；不能把新增模块自动换算成创新分。

面积单位已通过同服务器标准单元/SRAM LEF物理尺寸核对。候选占2.25mm²的13.0662%，剩余1.956011484mm²。指南确认综合面积就是预算核验口径，因此无需再以布局利用率推算该限额；最终仍须核对组委会宏面积统计与指定库身份。

当前8路PE阵列层级面积约0.017273mm²（5.9%），bias缓存层级约0.110988mm²（37.8%），16个权重SRAM宏约0.146376mm²。算术资源投入较少，值得研究更高并行；但目前10,240bit bias缓存采用Reg及选择逻辑，面积/活动成本高。原始层级数据见[area.rpt](validation/xu-hw-optimization-20261102/ppa/candidate/area.rpt)。

上述功耗/能量仅为wrapper、单真实layer0、RTL活动映射到布局前网表的估算，不含E203/互连/共享SRAM，不可代入正式能耗评分。总能量可能受CPU执行时间和存储活动改变影响，必须重新测量。H1+H2吞吐更高、面积和wrapper能量更高，尚不能认定为总分最优。

候选12层阶段占比为写回47.4291%、W装载21.7281%、X装载8.3521%、计算等待15.8876%，其余6.6030%。若只有计算等待按输出列PE数理想缩短，其他阶段固定：

| --- | ---: | ---: |
| 32 | 14,543,016 | 1.1353× |
| 64 | 14,215,128 | 1.1615× |

## 下一轮实施顺序

### S0：资格与正式测量口径

- 固定当前signed16/40/48及数值配置，恢复可复现的权重、FP32参考和验证集误差评估，生成逐层SSE/reference energy/样本清单/模型及工具SHA。按指南准备600样本软件评测接口及正式抽样后的复核；官方未公布的600样本清单不自行冒充。开发调试遵守训练/验证/测试划分。
- RTL验证使用12层参数、多样本输入及独立组件向量，最终接入组委会12个性能任务；指南不要求把全部600样本逐一做SoC RTL仿真。所有RTL结果须与提交的软件数值模型逐位一致。
- 补充综合前后功能一致性证明（门级回放或等价流程），不能以DC link/check_design代替。
- 核实有效SDC、SRAM模型/adapter及全SoC150MHz检查；当前wrapper仍有hold违例和未测路径，不能通过false-path等隐藏问题。
- 建立相同12任务窗口、包含E203/互连/共享与内部SRAM的全范围活动功耗与单任务能量测量。覆盖不足使用明确建模/传播并披露，不按零计。

资格工作和下面架构筛选可在独立副本并行进行；未通过资格的候选不标记比赛合格。当前只已有开发整数/RTL回归、固定单样本silence 12层、wrapper综合STA和wrapper活动功耗，均不能替代上述完整范围。

### S1：先降低缓存及接口代价

- 独立构建真正移除全bias缓存门电路的H2-only候选。目前H2运行模式使用完整新RTL，不能当作H2-only硬件面积/能耗数据。
- 对比SRAM型bias存储及当前tile偏置暂存/预取，减少全数组Reg和大组合读选择。优先验证指定、实际可用宏；同步读延迟、完整上传和预取开销计入任务。数据存储改造同时对齐指南指定SRAM的要求，XRowBuffer现有Reg实现也需逐项核对。
- 做写使能、数据通路静止及可综合低切换控制；时钟门控仅使用工具/库支持流程，不自行拼门产生时钟。
- 比较旧B0、真正H2-only及低功耗缓存候选的同口径(T,E,A)，保存非支配项。

### S2：减少搬运和软件逐组开销

- 独立评估W/X地址流或批量访问、group外层硬件控制、结果FIFO/批量读回，减少CPU逐字设地址、逐组启动轮询及结果索引控制。
- 评估X/结果双缓冲，重叠装载、计算和写回。现有权重宏为1RW且读写互斥，不能假设可无代价同时加载/计算。
- 若采用DMA主端口，先核对平台允许接入/仲裁方式，保留E203负责驱动和任务管理；不改固定总线/共享SRAM，不假设无限带宽。所有新增接口面积、仲裁、等待、全范围能量和最终响应退休均计入。
- 任务开始前清空/刷新数据参数状态，不跨任务复用已加载权重来绕过计时；双缓冲不能把本任务装载移出窗口。

### S3：32/64 MAC并行候选

- 改善搬运后，在同一基线上独立比较32路输出列并行，再判断64路；也可先做32路小实验验证瓶颈预测，不承诺4倍整体加速。
- 联动参数化PE阵列、group位宽/数量、权重bank/地址、bias读取、结果接口和固件/TB契约，不仅修改`Seq.fill(8)`。
- 固定W逻辑容量32KiB，比较真实可用宏的bank组织与碎片。例如32列并行需每bank512个16bit权重，64列需256个；沿用1024深度宏会增加物理容量，使用128宏会增加小宏外围和选择成本。以实际综合决定面积/时序/功耗。
- 同时评估二维tile候选，例如16输出列×4输入行形成64 MAC/拍，复用权重与X广播；这是待验证架构，不是既有测量结论。
- 保持原数值格式和模型不变，先隔离架构收益。只有独立数值误差/得分研究时才改变格式，并另设完整基线。

每项按本地数值/接口检查→同服务器VCS真实12任务→同库综合/时序/等价→全范围能量的顺序形成可恢复候选。低影响本地筛选可提前淘汰错误实现，最终保留依据改为资格、(T,E,A)非支配关系和评分敏感性。全部实现/活动/网表身份及日志SHA按上一轮交付方式记录。
