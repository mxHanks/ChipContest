# 64PE原SystemBus32整改版硬件/软件交接

**硬件候选已冻结；生产边界与比赛资格仍在整改。** 本文件取代旧DMA64候选的接入与性能建议；历史证据保持原样。硬件子提交`bde23ba`（父为`62ff097`），父子分支均`codex/s3-y32-compliance-20261113`。

## 选定硬件

生产同时启用`XU_MATRIX_DMA`、`XU_MATRIX_DMA_SYSBUS32`、`XU_MATRIX_X_SRAM`，禁止`XU_MATRIX_DMA64`和生产`XU_SYSBUS_TEST_LOADER`。两个X选择宏不同时成立时保留原B41默认/旧回退行为；旧支路不是本次比赛接入方案。

64PE=8行×8列，99尾行仅3路有效；共享16颗W宏和1颗bias宏；16颗指定RAMSP1024X16作双set X缓冲（有效2KiB、物理32KiB）。新内部33宏，全数字SoC353宏，其中CPU64/shared256复用。两次真实32位W读取仅在DMA内部拼成4个16位bank输入，外部接口保持32位/mask4。没有共享容量扩张、旁路SRAM口或更改CPU/LSU/BIU原在途控制。

CPU与DMA作为原SystemBus源，经同一原`e203_subsys_mems/u_sirv_mem_fab`、原32位共享端点访问。自建参数加载测试刺激也在该原fabric入口，所有载入通过相同规定通路；生产不暴露测试端口。答疑2要求队伍自行实现加载环境，不等待官方示例。

数值：X/W INT16，bias signed40，内部41位有界累加，RNE9到Y32，解码指数−18。共享SRAM保存完整99×256个32位原数值输出（101376B），不得再压缩。

## 驱动顺序与ABI

MMIO与地址表、完整步骤见`experiments/s3-y32-compliant32/validation/README.md`；可编译驱动参考`sysbus32_main.c`。基址`0x10042300`，ID`0x444d4131`，cap在`+0x4c`返回`0x00082001`。四描述符`+0x10/14/18/1c`分别X/W/bias/Y，缺省共享地址`0xa0000000/0xa0008000/0xa0018000/0xa0020000`。

1. 等前任务DONE、无ERROR，fence后完整读取或使用前任务输出。首次ERROR中止，不盲目重试部分写回任务。
2. CTRL`+0x04=1`真实清零，等待`!BUSY && CLEAR_DONE`，检查错误并fence。每任务W16384+bias768+X16384=33536个16bit数据地址真实写零，算术、FIFO、bias缓存与DMA两个32bit暂存同时归零。X每颗1024地址全覆盖；bias仅768个映射数据地址，其余256不存任务数据。
3. 通过原SystemBus载入本任务X6336个32位槽、W8192个32位packed16词、bias512个32位词，等全部响应退休。每任务独立参数，不跨任务保留参数换取吞吐。
4. fence，写四描述符，fence，CTRL=`0x802`启动64PE。轮询status`+0x08`的BUSY/DONE/ERROR，错误码`+0x0c`。不使用NICE/POP指令调度结果。
5. DONE仅在所有Y写响应退休且内部请求排空后成立，fence后通过规定共享口取完整矩阵。任何DMA源/目的区必须处于512KiB共享范围，Y不与源重叠。

每任务DMA15040读+25344写，40384次请求/响应、3168结果POP，64PE模式26624 MAC步。描述符任务不可在ERROR后原地无条件重试。
