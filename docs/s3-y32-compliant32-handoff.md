# 64PE原SystemBus32整改版硬件／软件交接

当前选择为**374宏、原32位System Bus、GPIO→CPU真实装载**的隔离冻结候选。它已通过CPU单任务，完整12任务及等待测试正在运行；同版本综合、150MHz STA、网表功能与功耗尚未验收，不能宣称已满足全部比赛要求。

父／子分支均为`codex/s3-y32-compliance-20261113`。已安装子提交`bde23ba`仍是353宏回退版；374宏源在`experiments/s3-y32-compliant32/storage-macro/`生成并冻结，尚未安装。最终取版必须核对源清单及完整12收据，不能仅按分支名。

## 选定结构

同时启用`XU_MATRIX_DMA`、`XU_MATRIX_DMA_SYSBUS32`、`XU_MATRIX_X_SRAM`、`XU_MATRIX_STORAGE_SRAM`；禁止`XU_MATRIX_DMA64`及`XU_SYSBUS_TEST_LOADER`。未选择新模式的旧接口／回退保留，14次实际预处理比对通过。

64PE为8行×8列，99行尾组只启用3行；X/W INT16、bias signed40、41位有界累加、RNE9到Y32、解码指数−18保持原数学。共享SRAM保存完整99×256个未再压缩的Y32（101,376B）。

内部指定`RAMSP1024X16`共54颗：W16、bias1、双set X16、结果21；加上复用CPU64、shared256，全SoC共374颗。X有效2KiB／物理32KiB，结果逻辑656B／物理42KiB，全部物理容量计费。结果直接由同步宏Q按标量发送，直到Y写响应退休才释放；无结果寄存器FIFO、整行快照或bias预取slot。bias的32位暂存只装配当前40位操作数。

CPU与DMA是生产仲裁两个源（N2/PW1），均经过原`e203_subsys_mems/u_sirv_mem_fab`及原32位共享端点；两笔W只在DMA内部拼装。外部数据32位／mask4，无扩宽口、共享SRAM旁路或TCM张量替代通路。CPU/LSU/BIU原控制及在途配置不变。

输入由现有GPIO进入CPU：GPIOA20 REQ，A21 ACK、A22 READY、A23 ERROR，GPIOB为32位数据；REQ前数据至少稳定3个HF沿，保持到ACK。CPU读取GPIOB，经原LSU/BIU写共享SRAM，fence后应答。测试台只初始化启动固件、驱动外部引脚及只读观察，不层次写tensor／结果；GPIO传输和软件等待全部计时。

## 驱动顺序与ABI

参考`experiments/s3-y32-compliant32/validation-gpio/gpio_main.c`和该目录README。MMIO基址`0x10042300`，ID`0x444d4131`；cap `+0x4c=0x00082001`。X/W/bias/Y描述符为`+0x10/14/18/1c`，缺省共享地址为`0xa0000000/0xa0008000/0xa0018000/0xa0020000`。

1. 等前任务结束，检查ERROR，fence后读取完整输出。首次错误中止，不盲目重试部分写回任务。
2. CTRL `+0x04=1`，等待`!BUSY && CLEAR_DONE`，检查错误并fence。每任务W16384、X16384、结果21504、bias768，共**55,040次16位物理写零**，ACC／装配／描述符／所有权状态也清零。bias最后256地址未映射为任务数据，不声称已清零。
3. READY后接收15,040个32位源词：X6336、packed W8192、bias512。每次共享写响应退休并fence后才ACK；每任务独立参数。
4. fence，写四描述符，fence，CTRL=`0x802`；轮询status `+0x08`及错误码`+0x0c`。
5. DONE只在全部Y写响应退休、内部排空后成立。fence后CPU经原共享通路读全部25,344个Y32，不通过NICE／POP指令调度结果。

每任务DMA15,040读、25,344写，共40,384个请求／响应；内部标量退休25,344次，兼容分组POP计数3168，64PE MAC步26,624。

## 已验证范围

21宏候选通过核心60组合（12层、行数1／3／8、停顿0／31／255、符号极值、复位／清零）及DMA完整12单元：304,128个Y32一致，包含读写错误、在途复位、参数切换及末Y响应扣留。单元总926,858拍，**不是CPU整机吞吐**。3宏窄结果候选也通过，但同口径1,525,920拍，因较慢未选。原件在`docs/validation/s3-y32-compliant32-storage-20261113/`。

生产N2／374宏CPU任务0（含非零前态warmup）已通过：25,344个Y32写及CPU公开读回一致、15,040次GPIO ACK、55,040物理写零；source地址顺序、响应退休与完成顺序核验。含clear至末Y为**1,492,424拍**，首GPIO数据至末Y1,491,333拍，其中装载1,315,983拍、clear1027拍、DMA175,261拍。按假定150MHz换算约100.51 task/s；单任务不能代替完整12，150MHz也未获STA证明。

单层冻结包`build/compliant32-20261113/cpu-gpio-storage21-single-delivery-r1/gpio-storage21-single-task.tar.gz`，SHA256 `3a0f1d073af1ff5a4935bb770ab48dc378d51db57dbb56368858ea9a87cf3f65`。完整12与两种wait31复用相同binary／ELF／向量，正在运行。

真实公开音频开发评测保持原模型162个变量逐值一致：600条开发样本（599条原WAV及1条明确的合成静音），各层最大NRMSE0.0131066%（门槛3%）。CPU向量来自同一音频导出。这不是组委会最终600条选择，也不是整机跑完600×12层。

旧353宏／三源测试loader完整12曾得3,568,690拍、约504.3868 task/s；其仲裁硬件与生产N2不同，只保留历史证据。旧64位口约4197 task/s也不能用于当前候选。

## 原生PPA与剩余验收

用户已协调一个独立最多2核作业。旧353宏生产配置DC约1275秒、PT约37秒；原件已完整回收、身份重放通过，**595项时序违例，未闭合**。最差setup −5.16538525ns在高扇出调试时钟输出，最差hold −0.13472039ns在bias写数据；另有权重／GPIO等接口保持、门控保持、复位移除及电气／覆盖问题。工具返回码0不是时序通过。

353宏计费命名范围为523,232.351262个库面积单位；全SoC标准单元加33内部宏保守上界为657,808.986462个库单位。库面积量纲及官方SRAM计价未核定，不能直接宣布mm²或≤2.25mm²通过，更不能冒充374宏面积。
