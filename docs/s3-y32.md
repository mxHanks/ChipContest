# S3-Y32 开发交接

> 历史说明：本页对应早期 8 PE 开发版本。当前 main 的 64 PE / 1064 修复候选请见[当前交付入口](../submission/README.md)，本页命令只适用于对应历史提交。

本分支集成 32 位结果、共享内存 packed16 权重、NICE drain8 和 bias SRAM 双组预取。保留 8 PE、两槽结果 FIFO、16 位输入和权重、40 位偏置。E203 子模块锁定配套提交，另包含 UART 组合赋值修复。

## 功能状态

| 同平台 12 项 FFN1 任务 | S3-Y32 主组 | 新 ABI 寄存器 bias 控制组 |
|---|---:|---:|
| 有效任务周期 | 7,043,916 | 10,701,840 |
| 单独统计的参数清空周期 | 2,380,992 | 2,433,180 |
| 输出数 | 304,128 | 304,128 |

自有 Linux 的通用 SRAM RTL 回归保留原平台与设计断言。UART 修复前后，主组和控制组各 12 项的周期、输出、固件加载字节和 HCLK 摘要一致。4,445 个开发音频样本的 Y32 最差层 NRMSE 为 0.0132832531%，无溢出。功能任务集与开发精度数据集是两套输入。

正式验收仍需关闭 150 MHz 整机 setup/hold 违例，确认新网表中 UART 端点，完成厂商 SRAM 的严格门级与等价范围审查，核实全 SoC 单任务能耗、净新增面积和清空政策。官方 600 样本精度另行验收。

## 开发入口

```sh
git clone --branch s3-y32-development --recurse-submodules https://github.com/mxHanks/ChipContest.git
cd ChipContest
python3 -B -m unittest discover -s tests/numeric -p 'test_s3*.py'
```

固件在 [tests/e203/firmware](../tests/e203/firmware)。有 VCS 和 RISC-V 工具链时，完整功能回归使用 [fresh-reset 任务入口](../tools/ppa/s3_task_campaign.md)。SRAM 与寄存器 bias 需要分别安装相应 RTL 和匹配的固件配置。

现有 PPA 脚本仍以固定的原始基线 HEAD 加源码字节清单记录来源。若要为同一套源码重新生成 PPA 输入，可在一次性克隆中用下列命令恢复基线身份，同时保留发布版工作树中的源码。执行后直接运行冻结入口，避免再次更新子模块把工作树切回旧源码。

```sh
git -C third-party/e203_hbirdv2 switch --detach HEAD
git -C third-party/e203_hbirdv2 reset --mixed --quiet a0767db69628ef30e53de2d1e93dd0360c0ccf76
git switch --detach HEAD
git reset --mixed --quiet ddccdc95b9aa1521c3e404b9d9f95b788fdae8a5
python3 -B tools/ppa/s3_soc_implementation.py freeze \
  --profile s3-y32-bias-sram --out /path/to/new-freeze
```
