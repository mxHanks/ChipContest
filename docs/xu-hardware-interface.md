# xu H1/H2 硬件扩展接口

该接口在原 `ACCEL_BASE=0x10042000` 寄存器区增加地址，原 `0x000–0x03c` 的 ID、启动、W1C、数据宽度和读写语义保留。8 PE、signed16 X/W、signed40 bias、signed48 Y 以及每组 64 次 MAC 不变。固件必须先读取 capability，防止将旧 RTL 当作扩展硬件使用。

| 偏移 | 名称 | 语义 |
| --- | --- | --- |
| `0x040` | CACHE_CTRL | bit0 为完整 bias 缓存使能，复位为 0；仅写 mask[0] 有效，其余位读 0 |
| `0x044` | CACHE_ADDR | 选择 bias 列号 0–255，仅低 8 位及 mask[0] 有效 |
| `0x048` | CACHE_LO | 所选列的低 32 位，四个字节分别由写 mask 控制 |
| `0x04c` | CACHE_HI | 所选列的高 8 位，写入截断到低 8 位，仅 mask[0] 有效；读时高 24 位为 0 |
| `0x050` | CAPABILITY | 只读 `0x58550003`，标识本版完整 bias 缓存和固定结果窗口 |
| `0x080 + 8×lane` | RESULT_WINDOW_LO | lane 0–7 的结果低 32 位，只读 |
| `0x084 + 8×lane` | RESULT_WINDOW_HI | 同 lane 的结果高 16 位，零扩展至 32 位，只读 |

固定结果窗口无指针和读副作用；旧 RESULT_INDEX 不受窗口读取影响，结果在下一次计算更新前保持。固件仍将结果高字从 signed16 扩展到 signed32，再将两个字按原行优先顺序写回共享 Y。

完整 bias 缓存由 Chisel `BiasBankCache` 实现，为八个 bank、每 bank 32 个 40-bit 项，共 10,240 bit（1,280 B 原始数据），使用无复位寄存器存储。此容量不是 SRAM 宏容量或综合面积。数据未初始化时不可启用：每任务必须在空闲状态完整刷新 256 项，并保持计算期间的 group、模式、参与计算参数稳定。旧 8 槽 bias 路径在复位后有效。忙时参数写入与旧接口一样属于调用方违反约束，不提供额外忽略语义。

H1 固件在完整 W 装载之后依次写 CACHE_CTRL=0、256 组 ADDR/LO/HI、CACHE_CTRL=1。全部共享读取、上传及两笔模式写均位于既有计时窗口内，每任务不复用上次缓存。H2 只替换结果读取地址，省去每个结果的 RESULT_INDEX 写，不改变读取和共享写回次数。

| 每任务契约 | 软件最优 B0 | H1 | H2 | H1+H2 |
| --- | ---: | ---: | ---: | ---: |
| 共享读 | 23,232 | 23,232 | 23,232 | 23,232 |
| 共享写 | 50,688 | 50,688 | 50,688 | 50,688 |
| bias 数据/索引 MMIO 写 | 76,032 | 768 | 76,032 | 768 |
| 缓存模式 MMIO 写 | 0 | 2 | 0 | 2 |
| 结果索引 MMIO 写 | 25,344 | 25,344 | 0 | 0 |
| 计时窗口 MMIO 总写 | 156,326 | 81,064 | 130,982 | 55,720 |
| START / done | 3,168 / 3,168 | 同左 | 同左 | 同左 |
| MAC 有效拍 | 202,752 | 同左 | 同左 | 同左 |

MMIO 响应在命令接受边沿锁存；受阻时保持 valid/data，不重复执行写入。扩展字节写及结果窗口由独立接口测试覆盖，SoC 任务继续检查全部结果和最终写响应退休后的 ACK。

六阶段计数对新地址补充分类：缓存控制/地址/数据归 bias，启用模式的写响应退休后结束；窗口读取归 writeback。共享读分类、真实首读/末写响应窗口和背压激励不变。阶段用于解释总周期，不表示纯总线延迟。
