## 目标及完成定义

在独立候选中完成 **8 行×8 列 64 PE＋共享单套 W/bias＋真实 64 位共享存储搬运**，实现、验证和交付完整 4k 候选。4 行×16 列只在主方案的实测瓶颈表明确有需要时启用，首版不同时改变累加位宽。

Goal 完成必须由**同一个冻结候选**同时满足：

1. 真 CPU 完整 12 任务，所有 **304,128 个 Y32 逐位一致**；预热和单任务输出也核对。每任务输入与参数身份独立且可复查。
2. 主口径包含真实清零，12 任务 **≤450,000 拍**，逐任务目标 **≤37,500 拍**；不得用不同任务的超时相消。按已验证的 150 MHz 达到 **≥4,000 task/s**。clear 后 gap 单列，并补报含 gap 吞吐和 CPU 提交/同步周期。
3. 完整同源时序满足 **150 MHz**：setup、hold、gating、reset、DRC 和时钟/端点覆盖均检查；所有未测试/未约束项有真实来源与适用性处置，不能靠无依据例外或删除检查制造通过。
4. 按比赛正式计费范围，面积 **≤2.25 mm²**；核实库面积量纲、SRAM 官方计价和新增接口/仲裁归属。原 1.25 倍限制已由用户明确替换，不再用于本轮否决。
5. 数值、协议、物理清零、背压、错误、复位、在途排空、任务隔离、内存可见性与旧接口回退均通过。
6. 提交完整源码/固件/向量/工具/库/时钟身份、原始日志、失败记录、分阶段数据、面积与时序、可复现包、handoff 和本地版本关系。

“计划完成”“原型通过”“预算上可行”“按假定频率换算”均不等于上述目标完成。性能或资格缺项时保持真实状态，不以时间用尽替代成功。

## 周期与存储预算

| 主阶段 | 候选预算 |
| --- | ---: |
| 完整物理清零 | ≤1,100 拍 |
| W/bias 全部物理提交 | ≤6,000 拍 |
| 首 X 至末 Y 写响应 RUN | ≤29,000 拍 |
| 其余启动、阶段衔接与完成 | ≤1,400 拍 |
| 主口径合计 | **≤37,500 拍/任务** |

预算不是新测量。可根据完整证据调整阶段分配，但不改变计时边界、完整总上限或功能约束；调整须留下原因和新账本。内部选型争取 ≤35,625 拍，预留约 5% 周期空间。

64 PE 主方案纯 MAC 为 26,624 拍；现约 68 拍/组的静态模型为 28,288 拍，首尾与气泡必须实测。真实64位口保留旧X布局共20,192 beat/任务；packed-X降至18,608，但首版可以保持旧软件布局。W/bias 共4,352宽beat，bias本地提交必须与W装载重叠，不能把旧12,695拍简单减半。

新增存储账本至少包含 X 双缓冲 **2 KiB**、两槽 raw48 结果 **768 B**、DMA 快照、bias 暂存、请求归属与错误排空元数据；W 仍16宏、bias仍1宏。所有新增存储也要验证脏态物理清零及任务隔离。

## 失败处置与停止条件

1. 真实接口仍只能串行服务旧32位字，或混流不能满足预算：先修接入口/仲裁，不继续扩PE或盲目深FIFO。
2. 已确认必须修改CPU内部控制，或明确不符合赛题允许边界：停止该支并记录原因，保留其他可验证结果。材料缺失只标资格缺项，不编造许可或未经证据认定违规。
3. 数值、物理清零、错误、reset或响应归属失败：冻结性能结论，先定位并修复，再做有收益的完整跑分。
4. 64 PE 调度达不到周期预算：用阶段计数定位瓶颈；仅有证据时评估4×16或更深解耦，不默认增加PE、宏或通用DMA。
5. 面积超2.25mm²或150MHz时序失败：按实际分解优化/回退，修复后重新绑定功能与周期；不改计费范围、不减输出、不放宽语义。
6. 达到用户明确的截止：停止新增实验，优先封存最强可信候选；报告未完成项，不能擅自延长或将Goal标成功。

Goal 只有全部完成定义满足才标 `complete`；用户明确要求暂停才标 `paused`；`blocked` 仅按工具规定在同一阻塞连续至少三个Goal回合且确无可推进工作时使用。当前已有本地实测进展，但最终时序、面积和资格未通过，不得标 complete。工具最新返回 active，继续执行范围以用户本轮指示和时间截止为准。
