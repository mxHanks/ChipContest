# xu S2 搬运实验实施提案

2026-11-02 源码检查提案，未实现、未测周期或 PPA。维护标识：xu。基线是本副本的 H1+H2（8 PE、signed16 X/W、signed40 bias、signed48 Y），与 S1 H2-only、SRAM bias 候选分开保存。数值、共享存储槽格式、E203 主导调度、任务装载及最终 Y 响应退休窗口不变。

## 先做什么

建议先在独立副本实现一个小的 wrapper 装载流适配器，依次打开两个独立功能：

1. **S2a：W/X 标量自动索引。** 新地址接收一个 signed16 元素，硬件游标自增。W 游标按共享内存的 `k*256+c` 次序，wrapper 直接转换成现有 bank/addr，不再让 CPU 按 bank 跨步读取。只改手写 wrapper 和固件，不改 Chisel 计算、X 缓冲、权重宏或 bank 接口。
2. **S2b：同一适配器接收 packed2×16。** 一个 MMIO 字携带两个相邻元素，先用两个内部写周期复用现有标量端口；响应在两次写均生效后才产生。仍不改 Chisel/宏。保持 S2a 可单独运行，对比额外 CPU 打包指令及两周期适配的实际代价。
3. 仅当 S2b 的内部写串行或背压确实限制收益，再做 **S2c：相邻 bank 并行写**。这一步需要扩大 Chisel 装载接口，独立综合和测量，不预设其比 S2b 更快或更省电。

这比先加 DMA、自动整行计算或双缓冲更容易隔离：不接新主端口，不动固定互连，不增加权重容量，不需要 bias 缓存选型先结束。软件展开只能省循环控制，不能删掉既有 `volatile` 地址 MMIO 写；S2a/S2b 删掉的是实际事务。不过事务减少不等于已证明总周期、能量或评分改善，仍以同工具链实测为准。

已有 12 任务的六阶段中，W=3,587,388、X=1,378,968、bias=93,312、compute=2,623,104、Y=7,830,708、other=996,864，总计 16,510,344 周期。W/X 是合适的小实验入口，但 Y 仍占 47.4291%，不会因 W/X 流接口自动减少。

## 地址变换及数据格式

W 的流游标 `s = k*256+c`，`0 <= s < 16384`：

```text
bank = s[2:0]                     # c % 8
addr = {s[7:3], s[13:8]}          # (c / 8)*64 + k
```

这正好保持现有布局 `bank[c%8][(c/8)*64+k] = W[k*256+c]`。CPU 可顺序读取原始 32 位共享槽，不需要预转置、额外暂存或修改夹具。标量写取 `data[15:0]`。packed 写的低 16 位对应游标 s，高 16 位对应 s+1；要求 s 为偶数。对 W，它们位于同一 addr 的相邻 bank 对 0/1、2/3、4/5、6/7。对 X，它们是同一行的相邻 k。

共享 X/W 仍各占一个 32 位槽。CPU 打包应按低 16 位截断，例如 `(uint32_t)(uint16_t)a | ((uint32_t)(uint16_t)b << 16)`；不能因当前夹具高位为零就删除保证该语义所需的操作。两元素仍需两次共享读。不得在任务窗口前预打包到 DTCM，再只统计 MMIO。

## 提议的可发现 ABI

原 `0x000–0x050` 和 `0x080–0x0bc` 语义保持；使用当前空闲的 `0x054–0x06c`。没有全局模式切换；旧 DATA 地址永远保持旧语义，新行为只由新地址触发。

| 偏移 | 新名称 | 提议语义 |
| --- | --- | --- |
| `0x054` | W_CURSOR | RW，原始 W 元素序号 0..16384，含终点哨兵；一次任务显式写 0 |
| `0x058` | W_STREAM16 | WO，一次写一个 signed16，完成后 W_CURSOR+=1；读 0 |
| `0x05c` | W_PACK32 | WO，一次写两个 signed16，完成后 W_CURSOR+=2；读 0 |
| `0x060` | X_CURSOR | RW，当前行元素序号 0..64，含终点哨兵；每行显式写 0 |
| `0x064` | X_STREAM16 | WO，一个 signed16，完成后 X_CURSOR+=1；读 0 |
| `0x068` | X_PACK32 | WO，两个 signed16，完成后 X_CURSOR+=2；读 0 |
| `0x06c` | STREAM_STATUS | bit0=pending、bit1=sticky error，其余读 0；bit1 为 W1C，只有 mask[0] 有效，写其余位忽略 |

CAPABILITY 保留 `0x5855` 签名及 bit0=bias-cache、bit1=result-window，增加 bit2=W_STREAM16、bit3=X_STREAM16、bit4=W_PACK32、bit5=X_PACK32。H1+H2 上 S2a 为 `0x5855000f`，同时实现 S2b 为 `0x5855003f`；H2-only 对应 `...000e`、`...003e`。bit0 按所选 S1 实现实际存在与否填入，不能因固件不使用缓存而谎报硬件。

新固件检查签名和**所需 bit 的包含关系**，不再仅接受一个完整常量；旧固件的严格相等检查可能拒绝新硬件，保留这种可见的拒绝，不能为让旧固件误认而继续返回旧 capability。未实现的功能 bit 为 0，缺功能时新固件应在任务前返回明确错误，不静默回退到某个未记录的调度。新硬件上运行旧 ABI 对照时，只在对照固件中采用同样的签名/所需 bit 检查，保留原装载循环和事务；不修改历史冻结 ELF，构建身份另行记录。

### 写掩码、非法命令和 busy

- 新 CURSOR/STREAM/PACK 地址只接受对齐的全字写 `cmd_wmask=1111`；其他 mask 不产生任何内部写、不改游标，并在对应响应报告 `rsp_err=1`、置 sticky error。这样没有含混的半个元素更新或“部分写也自增”。旧地址继续保留旧有 mask 语义。
- CURSOR 的值须在上述闭区间内；STREAM16 需剩余至少一个元素，PACK32 需偶数游标且剩余至少两个。终点不回卷；非法值和溢出同样报错且不改变状态。
- `busy=1` 时新 CURSOR/STREAM/PACK 写报错且不操作，避免碰撞现有 1RW 权重读取及当前 X 行。旧参数地址的计算期限制仍按旧 ABI；不在本实验顺带改变它们。
- 新 data 适配期间置 pending 并禁止接受下一命令。START 到达时必须等 pending 完成且前响应可退休，不能在仅完成低半字时启动。START 仍只算一个 group；busy 时 START 仍按旧语义忽略，W1C 不变。
- 新流读取、状态读取不隐式改游标。复位清游标、pending、error，不声称清除 SRAM 数据；每任务仍完整刷新全部 W、每行完整刷新 X。

实现 `rsp_err` 时需改为与 `rsp_valid/rsp_rdata` 同槽的寄存响应错误位；受阻时三者一起保持。所有旧地址返回的错误位继续为 0。不能用组合 `cmd_*` 计算已经挂起的响应错误。

### 接受、内部提交及响应退休

S2a/S2b 都用保存的 beat 地址和数据驱动旧 core 写端口，而不是把游标直接连到旧 `w_addr_reg/x_addr_reg`：

```text
接受新流命令：保存完整 data、当前游标解码出的 bank/addr、1 或 2 元素计数
下一边沿：提交第一个元素
packed 的再下一边沿：提交第二个元素
最后提交边沿后：推进游标并置 rsp_valid；在 rsp_ready 前保持响应
```

这可用一个 32 位暂存寄存器、小状态机和地址暂存完成。不能接受命令时一边增加 `w_addr_reg`、一边发 `w_load_wen`：旧 core 在下一边沿看的是增加后的地址，会造成首元素错位。最后元素的响应也不能在内部写前退休。允许当前响应退休同拍接收下一命令，前提是当前内部写已全部完成；受阻响应不得重复触发写、重复自增或重放高半字。

## 固件顺序和确切事务数

为了不靠把新配置放到计时窗口之前来获得收益，W 第一次共享读必须先发生，然后才写 W_CURSOR=0。例如 S2a 先 `first=w[0]`，再写游标和 first，接着顺序读取剩下 16,383 元素；S2b 先读 `w[0]`/`w[1]`，再置游标及首次 packed 写。所有 X_CURSOR 重置也在窗口内。编译时保持 volatile 顺序，保留当前 ID/busy/CAP 检查和最终 fence。

以下为每个 99×64×256 任务的**接受事务数**。固定 H1+H2 bias 调度、group 调度及 H2 结果窗口；MMIO 读的轮询次数由实际运行决定。

| 计时窗口内写事务 | 既有 H1+H2 | S2a 标量流 | S2b packed 流 |
| --- | ---: | ---: | ---: |
| W 数据及索引 | 32,774 | 16,385 | 8,193 |
| X 数据及索引 | 12,672 | 6,435 | 3,267 |
| bias 上传及两次模式写 | 770 | 770 | 770 |
| GROUP + W1C + START | 9,504 | 9,504 | 9,504 |
| MMIO 总写 | **55,720** | **33,094** | **21,734** |
| 比既有窗口少 | 0 | 22,626 (40.6066%) | 33,986 (60.9943%) |
| 12 任务 MMIO 总写 | 668,640 | 397,128 | 260,808 |

既有 W 完整函数实际上有 8 BANK + 16,384 ADDR + 16,384 DATA = 32,776 写；首次 BANK=0 和 ADDR=0 在首次共享 W 读前，故当前 TB 窗口只计 32,774，总写为 55,720，而完整函数为 55,722。S2 的一个 W_CURSOR 写显式放到首次共享读之后，所以上表没有把新初始化藏到窗口外。这也解释了为何不能直接用完整循环数差值计算新契约。

S2a：W 为 1 游标+16,384 数据；X 为 99×(1 游标+64 数据)。S2b：W 为 1+8,192；X 为 99×(1+32)。两者均保持：

| 固定工作 | 每任务 |
| --- | ---: |
| W / X / bias 共享读 | 16,384 / 6,336 / 512 |
| 共享总读 / 共享 Y 写 | 23,232 / 50,688 |
| 结果 MMIO 数据读（轮询之外） | 50,688 |
| START / core_done / MAC 有效拍 | 3,168 / 3,168 / 202,752 |
| 输出元素 / MAC 数 | 25,344 / 1,622,016 |

S1 真 H2-only 加 DTCM bias 调度也可复用流适配器；其每组 bias MMIO 写保留，以上总写需加 75,262，S2a=108,356、S2b=96,996。这个差额是 bias 调度差异，不能记成流接口收益。S1 SRAM bias 若保留原缓存上传 ABI，上面的 H1+H2 事务表原样适用；若其上传增加握手/事务，应单列新增契约。

## 后续独立选项

### S2c：packed 并行写和交错 bank

W 的偶数 row-major 游标已保证两个元素落在不同 bank、同 addr。扩大 `LinearComputeCoreIO`、`LinearCachedCore`、`WeightBankArrayIO` 的装载口，给两个被选 bank 各自的 signed16 数据及写使能，可同拍写两片既有宏，不增加权重容量；保留原标量加载口及原 bank 布局。X 可临时增加两个相邻地址写使能，或改成偶/奇两 bank；若 S1 将 X 换为 SRAM，须选择允许两个 bank 各写一次的真实宏组织。不能在现有单写端口输入 32 位就声称已完成两元素并行写。

S2c 与 S2b 的外部事务数完全相同，区别仅在内部提交时间、背压、接口逻辑及综合结果。先测 S2b 可以判断是否值得承担这次 Chisel/生成 RTL 联动。

### 自动 group、结果 FIFO 和 packed48

自动 group 需要每组 bias 可由硬件取得，最适合 S1 的全 bias SRAM 缓存；真 H2-only 的 8 个 bias 槽必须另有填充/握手，不能直接无人干预地跑完 32 组。先实现每行一次 START 的 32-group 控制以及至少两组结果存储，CPU 排空一组时可计算下一组；FIFO 满时在下一组 START 前停住，预留当前计算的入队空间，禁止覆盖未读结果。新自动模式通过独立 capability/地址触发，不改变旧 START 的单 group 含义。

在明确采用每行 GROUP_INIT+W1C+START 三次写的具体 ABI 时，group 控制可从 99×32×3=9,504 降至 99×3=297，少 9,207 写；core_done/MAC 仍分别是 3,168/202,752。新“row done”必须另有定义，不能把旧 done 当作整行已写回。实际轮询数和重叠收益待测。

当前 H2 已无结果索引写，单纯新增自动结果指针不能再省该项。8 个 signed48 结果合为 384 bit，可用 12 个 32 位 MMIO 字替代当前 16 字，每任务结果数据读从 50,688 降至 38,016，少 12,672（25%）；保留 signed64 共享 Y 槽时仍须 50,688 次共享写，CPU 还需拆分、符号扩展。读副作用 FIFO 必须在命令接受时只弹出一次并锁存响应，响应背压时不可重复弹出；空读应有明确有效/错误契约。

不要在此实验顺带把共享 Y 改为紧凑 6 字节格式。该格式可能把共享数据字数降至 38,016，但会改变主机/输出 ABI、检查器和处理开销，是另一个实验。

### X/结果双缓冲与权重 1RW

X 双缓冲可在计算当前行时装下一行，结果双缓冲可在 CPU 写回上一组时计算下一组；但单个 E203 同时承担 X/W 读取及 Y 写回，所有访问仍受真实 ICB 带宽和仲裁限制。没有新增主端口就没有自动共享搬运，CPU 需要显式交错调度。对已全量驻留的当前任务 W，X/结果双缓冲不要求复制 W；它也不允许在计算所有 8 bank 读取时向这些 1RW bank 装载下一任务 W。

若以后想重叠 W 装载，必须增加独立权重存储、改用允许的双端口宏，或让计算明确停顿/分时；其 SRAM 容量、面积、活动和控制代价要完整计算。任务间缓存清空、当前任务所有参数装载都留在窗口内，不跨任务偷偷复用 W。

## 最小变更清单与判定

S2a/S2b 最小实现文件：

- `third-party/e203_hbirdv2/rtl/e203/perips/accel_icb_slave.v`：新寄存器、CAP、串行加载适配器、按响应锁存的错误位；不改固定 SoC 或 E203。
- `tests/e203/firmware/accel.c`：独立 scalar/packed 路径、顺序 W 读取、严格 CAP 检查；`accel.h` 仅在需要明确新返回码时变更。
- `tools/scripts/xu_firmware_contract.py`、`tools/scripts/e203_soc.py`：增加明确的流配置及上述精确契约，保留现有配置/旧结果解释；不用一个新开关偷偷覆盖旧 schedule。
- `tests/e203/tb_accel_soc.sv`：只观察新流地址及响应元数据，W/X 阶段结束于最后内部写的响应退休；仍核对每个 Y、最后响应退休及 ACK。内部 pending/串行周期全部进入原窗口，不能只记录命令接受拍。
- `tests/e203/tb_xu_cached_wrapper.sv` 或相邻专用小 TB：在现有直接接口检查中覆盖新语义，不搭建另一套测试框架；本提案不实施测试代码。

本地先做少量但有效的检查：W 游标跨 bank 对、c=255→下一 k、最后元素；X 0/63、极值 signed16；标量/packed 与旧地址混用但不共享指针；非法 mask/奇数 packed/终点溢出/busy 写不操作；START 在最后 packed 写后不早启；命令与响应独立背压下每元素恰写一次。已有全部旧接口用例继续通过。

随后用同版 SiFive GCC 10.2.0、同 `-O2`/已有结果展开及掩码实验设置，分别跑旧 ABI、S2a、S2b 的 synthetic2/real12。冻结每个候选的源码/RTL/ELF/活动身份，比较完整周期及阶段、准确事务、综合/150MHz 时序和全范围每任务能量。S2b 若输给 S2a 就保留 S2a，不以事务数替代实际性能选型；进入总分候选前仍须 S0 资格及同配置 (T,E,A)，不得将 S1 的面积/能量拼到 S2 的周期。
