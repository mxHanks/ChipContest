# B41 严格符合官方 Q&A 的实现方案

> 状态：方案文档，不代表当前项目已经通过官方验收。
>
> 原则：所有 RTL、固件、测试台、模型和报告都必须按官方 Q&A 的明确答复执行，不使用解释空间规避约束。

## 1. 冻结的正式配置

- 计算阵列：64 PE，作为唯一正式提交配置。
- 数据类型：signed16 输入和权重、signed40 bias。
- 内部优化：`ACC41 + engine result41 + result FIFO41`，但必须保留完整范围证明、RTL/模型逐位一致性和门级等价证据。
- 输出：完整 `Y[99][256]`，每个结果为 Y32，最终舍入语义保持不变。
- 总线：原 SoC System Bus，原生 32-bit 命令、数据、响应和 4-bit mask。
- 频率：在声明的工艺角、供电、电压、温度和 RC 条件下实际闭合 150 MHz。

64 PE 只解决计算并行度，不能成为扩大总线或增加 SRAM 并行访问的理由。

## 2. 官方 Q&A 对照表

| 官方要求 | 强制实现方式 |
| --- | --- |
| DMA 必须集成到原 SoC 框架 | DMA 只能连接原 System Bus 和原共享 SRAM 路径。 |
| 参数加载必须真实发生并计时 | X、W、bias 都由正式固件通过平台接口传输；禁止测试台预加载。 |
| 计时范围 | 从第一笔输入/参数加载请求开始，到最后一个 Y 写响应完成；传输、等待、调度、计算和写回全部计入。 |
| PC 文件读取和一次性格式转换 | 可以排除，但格式转换必须可复现并有脚本、配置和哈希。 |
| 600 个样本 | 使用主办方随机抽取的 600 个样本做精度验收。 |
| 12 个性能任务 | 使用公开数据集中的 12 个任务，提交数据处理、执行脚本、日志和结果。 |
| 不得预加载任务权重 | 每个任务通过正式加载过程重新传输独立 X、W、bias。 |
| 固定一套性能/功耗/面积配置 | 64 PE、位宽、调度、打包和固件必须冻结为同一版本。 |
| 完整输出进入共享 SRAM | 保存完整 99×256 输出，禁止压缩、丢弃或仅保留部分结果。 |
| 平台接口保持 32-bit | 生产路径中不得出现 64/128-bit 外部端口、64-bit mask 或四 lane 同拍访问。 |
| 允许连续请求和仲裁优化 | 可以在原 32-bit 接口内做流水、背压和请求重叠，但不能改变接口宽度。 |
| 禁止 ITCM/DTCM 绕过 | 加速器只能经规定共享 SRAM 路径取数和写回。 |
| 禁止新并行 SRAM 通道 | 共享 SRAM 只能使用规定端口和协议，不增加独立 bank 访问路径。 |
| DMA 使用原 System Bus | 不增加新的 DMA master、互连或 TB-only loading interface。 |
| 规定的共享 SRAM 协议 | 读写、响应、所有权、错误排空和复位恢复均走原协议。 |
| 规定的结果写回路径 | 禁止 direct stream、独立结果通道或独立 SRAM 写口。 |

## 3. RTL 实现

### 3.1 必须移除的非合规路径

正式构建中必须移除或禁用：

- `XU_MATRIX_DMA64`；
- `xu_matrix_dma64`；
- `xu_dma64_shared_arb`；
- `xu_shared_icb_sram64`；
- `public_ingress` 测试台入口；
- direct stream、direct result 和独立 SRAM 写回路径。

当前 64-bit 接入在 [s3-y32-4k-handoff.md](s3-y32-4k-handoff.md) 中有明确记录，不能直接作为正式提交版本。

### 3.2 合规数据路径

1. `e203_soc_top`、`e203_subsys_top`、`e203_subsys_main` 和 `e203_subsys_perips` 统一使用 32-bit shared-memory 接口。
2. DMA 只实例化原 `xu_matrix_dma` 和原 `xu_dma_shared_arb`。
3. DMA 经 `sysmem_icb` 连接原 System Bus，再进入共享 SRAM。
4. 共享 SRAM 端点每次只接受一个 32-bit beat，使用 4-bit byte mask。
5. 可以在加速器内部暂存和拼接数据，但不能把内部暂存暴露成更宽的总线端点。
6. CPU 与 DMA 的仲裁、响应顺序、错误排空和复位恢复必须保持原协议。

### 3.3 32-bit 微事务规则

- W：一个 32-bit 字携带两个 INT16 权重。
- X：一个 32-bit 字携带两个 INT16 输入。
- bias：按两个 32-bit beat 读取后恢复 signed40。
- Y：每个输出使用一个 32-bit 写 beat。
- 允许设置小型请求 FIFO，连续发起原生 32-bit 请求；不得把它实现成新的多主互连或并行 SRAM 端口。

## 4. 计算、模型和打包

### 4.1 计算语义

- 保留 16×16 乘法、signed40 bias 和最终 Y32 舍入语义。
- 41-bit 收窄必须由全输入范围证明覆盖；不存在证明的位宽优化不得进入正式版本。
- 对外 raw48 接口采用符号扩展，确保旧模型、RTL 和 golden 逐位一致。

### 4.2 可复现打包

建立唯一 `pack32.py` 或等价脚本，固定完成：

- INT16 X/W 编码；
- signed40 bias 拆分；
- 地址、对齐和字节序；
- 32-bit beat 序列；
- RTL golden 和软件 golden 生成。

脚本、配置、输入向量、golden、固件镜像和 RTL 必须写入同一份 manifest 并记录 SHA256。禁止重新训练、微调、蒸馏或改变模型结构。

## 5. 固件和计时

每个任务必须按以下顺序执行：

1. 通过真实 32-bit 平台接口加载 X、W、bias。
2. 执行 `fence iorw, iorw`。
3. 发起完整清零并等待 `CLEAR_DONE`。
4. 写入描述符地址并再次执行 fence。
5. 启动 64 PE 的固定计算模式。
6. 等待 `BUSY=0 && DONE=1`。
7. 检查错误码、最后一个 Y 写响应和所有输出退休状态。
8. 读取完整 Y，并与 golden 逐位比较。

测试台不得调用 `prepare_layer` 一类的共享 SRAM 预装载逻辑，也不得在正式计时窗口外替换任务参数。

## 6. 验证和验收门槛

### 6.1 功能和协议

- 32-bit 地址、数据、响应、mask 和对齐断言；
- 无 64-bit 外部端口和无四 lane 同拍访问；
- 无 TB-only 参数加载；
- 无 ITCM/DTCM 绕过；
- 无 direct stream 或独立结果写口；
- 读写错误、背压、复位中止、在途请求和错误排空；
- 全部 99×256 输出逐位一致；
- 完整物理清零和任务间隔离。

### 6.2 官方工作负载

1. 单任务 32-bit RTL 回归。
2. 12 个性能任务，保存完整日志、脚本、结果和输入身份。
3. 主办方随机 600 个样本的精度验证。
4. VCS 四态仿真。
5. 综合后网表门级功能和等价验证。

### 6.3 PPA 和频率

- 在声明的 PVT/RC 条件下完成 150 MHz STA；
- 所有 setup、hold、clock、CDC、DRC 和覆盖问题必须有结论；
- 面积按官方 SRAM 和标准单元计价，确认不超过 2.25 mm²；
- 功耗必须覆盖规定全 SoC 活动窗口；
- 性能、面积、功耗和精度必须来自同一冻结配置。

## 7. 理论数据边界

当前任务每次包含：

- `99×64×256 = 1,622,016` 次 MAC；
- `99×256 = 25,344` 个 Y32；
- 现有数据布局折算到 32-bit 接口后，至少约 `40,384` 个 32-bit beat。

在 150 MHz、单个原生 32-bit 路径、无额外等待的理想条件下：

- 总线原始上限：600 MB/s；
- 仅按数据搬运估算：约 3,714 task/s；
- 若清零和控制开销也进入窗口：实际目标约 3,000～3,500 task/s；
- 64 PE 算术峰值：9.6 GMAC/s，即 19.2 GOPS。

这些是架构估算，不是官方成绩。当前 64-bit DMA 得到的 4196.64 task/s 不能直接提交。

## 8. 当前项目必须先修正的事项

1. 将生产构建从 DMA64 切回原生 32-bit System Bus。
2. 删除测试台参数预加载和 `public_ingress`。
3. 将真实加载、清零、等待、计算和写回纳入同一计时合同。
4. 删除或隔离所有 direct stream、独立写回和 SRAM bypass 实验路径。
5. 重新生成 32-bit 输入/参数/输出向量和 golden。
6. 用唯一冻结配置重跑 RTL、VCS、门级、STA、面积、功耗和 600 样本精度。

在以上项目完成并通过证据审查前，不能把当前仿真吞吐、面积库单位或诊断能耗写成官方最终成绩。
