# Production N2 / actual353 macro activity: preparation only

The previous N3 test-loader full12 capture was explicitly superseded and its
owned processes stopped. Its 353-macro single-task result remains a valid
generic-model functional/port-inventory experiment; it does not establish
power for the production N2 PPA configuration.

The final capture must start from the sealed **PASS GPIO/CPU-loading** source,
firmware and vectors prepared by `validation-gpio`. It must not change the
production RTL, widen System Bus, add a test-loader master or initialize
tensors/results through hierarchy.

Required seam before preparing the isolated observed copy:

1. Stable top-module/TB name and frozen source manifest, source/file order,
   production defines and firmware ELF/image hashes.
2. No `XU_SYSBUS_TEST_LOADER`; actual ingress N=2/PW=1 and all353 generic
   RAMSP instances (ITCM32, DTCM32, shared256, W16, X16, bias1).
3. Read-only names for HF clock, startup, task/layer/call identity, warmup,
   physical-clear command acceptance, the original cycle counter and final
   25,344th Y-response retirement.
4. CPU performs physical clear before the first GPIO source bit/handshake.
   The baseline must record the genuine first external input event, not
   substitute the first later System-Bus word for GPIO loading time.
5. Exactly one end-to-end PASS task0 from this frozen configuration, with
   its functional checker and complete counted window. This authorizes
   only then compiling/running the activity copy.

The observed copy may add only a read-only monitor include and a custom C++
trace main. If its top name differs, explicitly adapt the generated C++ class
and flattened monitor prefixes and seal those exact generated bytes. Reuse
the exact GPIO firmware and its existing boot-only initialization; do not
carry the historical N3 firmware or assume its ELF matches the new baseline.

The capture window must contain physical clear, every GPIO source transfer,
CPU parsing/loading, System-Bus writes, descriptors, computation, all waits
and final Y-write retirement. Open on the preceding HF falling edge and
close on the following HF falling edge only if this exactly covers the
baseline's inclusive counted task. Otherwise adapt and independently verify
the boundary rather than silently shifting it.

After observed task0 is numerically exact and its complete-cycle count
matches the same GPIO baseline, verify native FST time range and all3,530
macro-port declarations/initial values. Then reuse the exact observed
binary for full12 under an independent local supervisor; compare all layers
with the same frozen GPIO firmware/vector identities and full12 baseline.

All results remain **generic RTL activity**, pending final-netlist annotation
coverage, characterized SRAM power, legitimate clock/activity constraints
and whole-SoC energy measurement. No EDA is launched by this activity work.
